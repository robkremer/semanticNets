sn.view.graphics.viewEditing module¶

Editing in a graphical view (EditingMixin): one of the parts of sn.view.graphics.sngView.SNGView (see viewBase).

Created on Oct 18, 2026 (from sngView.py)

Code author: Rob Kremer <robkremer@me.com>

class sn.view.graphics.viewEditing.EditingMixin¶

Bases: ViewBase

Editing in a view (sn.view.graphics.sngView.SNGView): making new objects and relations (and where they go, and naming them), cut, copy and paste, copying a picture, erasing from the view or removing from the model, showing all of the model, and searching it.

addNewObjectMenus(menu, at, into=None)¶

Add the “new instance of Node”, “new subtype of Node”, “new instance of Relation” and “new subtype of Relation” cascades to menu: each with a submenu per model (this view’s, its super-models, then sn) of its types. What’s made is put at at (see _newObjectLocation()) – and, with into, contained in that context window’s pane (one undo for both): eg: the menu on a rule’s window, to edit it in place.

Parameters:

  • at (tuple[float, float]) – Where the menu was asked for (view coords).

  • into (tuple[VObject, str] | None) – (a context window, the name of one of its panes: see VObject.panes()), or None.

  • menu (Menu)

Return type:

None

_newAt: tuple[int, int, GraphObject] | None = None¶

Where the background menu that’s making a node was asked for (view coords), and the type it’s making one of, until it’s made (see makeMenu(), _newObjectLocation()).

_placeNew(vo, under)¶

Move a newly made view object to the nearest free place (see FindFree): below under (its supertype), if that’s given – or wherever the view’s dynamic layout puts it – and then let that layout adjust the rest (see ViewDoList.adjustAgain()).

Parameters:

  • vo (VObject)

  • under (VObject | None)

Return type:

None

doCopy(cut=False)¶

Copy what’s selected – or, if nothing is, everything shown – to the clipboard (see ModelContext.copy()), with how this view shows it, so a paste shows the copies the same way (see showPasted()). With cut, remove it from the model too (undoably) – only what’s selected: not everything, just because nothing is.

Parameters:

cut (bool)

Return type:

None

Parameters:

Return type:

None

pictureObjects()¶
Returns:

What a picture of the selection shows (see doCopyImage()): what’s selected, what’s in any selected context windows (at any depth), and the relations between any of those – as far as they’re shown; or, if nothing’s selected, everything shown.

list[VObject]

doCopyImage()¶

Put a picture of what’s selected – or, if nothing is, of everything shown – (see pictureObjects()), as it’s drawn (but without the selection’s handles), on the system clipboard, as a PNG: to paste into another program (see imageExport).

Return type:

None

doErase(vos)¶

Erase vos from this view (the model keeps their objects): one undo.

doEraseOthers(keep)¶

Erase everything but keep from this view (the model keeps their objects): one undo. Also kept are what keep needs to make sense (see keptWith()): the relations among the kept objects, the ends of the kept relations, and the context windows the kept objects are in. For working on a small part of a big view.

Parameters:

keep (list[VObject])

Return type:

None

doRemove(vos, confirm=False)¶

Remove the model objects of vos from the model – and so from every view of it: one undo. What can’t be removed here is left, with a message: what the reasoner inferred (mark it asserted first), and what’s in another model, or a write-locked one, or is a system object.

Parameters:

  • confirm (bool) – Ask first (eg: for a key press, which is easily made by mistake).

  • vos (list[VObject])

Return type:

None

PASTE_GAP = 40¶

The space (view units) left between pasted objects and what’s beside them (see _pasteOffset()).

showPasted(clip, made, at=None)¶

Show the objects just pasted (by SNGContext.paste()) as the view they were copied from showed them (see copying.Clip.geometry): the same sizes and layout – a pasted rule’s window with its contents in place – moved together (see _pasteOffset()). What wasn’t shown there (eg: an erased isa link) is shown, or not, as any new object is (see update()), but without asking for its name. Then what was asked to be copied is selected, so it can be dragged away at once.

Parameters:

  • clip (copying.Clip) – What was pasted (a copying.Clip).

  • made (list[GraphObject]) – The new objects, by entry of clip (see copying.pasteInto()).

  • at (tuple[int, int] | None) – Where to put the top left of them all (view coords), or None.

Return type:

None

scrollToShow(box, margin=20)¶

Scroll the canvas, if need be, so that box is in sight – the least it takes (as much of it as fits, from its top left).

Parameters:

  • margin (int) – Room to leave around it (canvas pixels).

Return type:

None

The graphics cursor’s position in view coordinates (ie: allowing for the canvas’s scroll position and the zoom). If the cursor isn’t over the canvas (eg: the command came from the text terminal), the top-left of the visible part of the canvas instead, so the result is on screen. (0, 0) if there’s no canvas.

_attachDanglingEnds(vo)¶

vo has just been added to the view: relations already here whose own endpoint is vo’s model object, but which were left dangling because it wasn’t shown (eg: top – see VRelation._resolveEnd() – or an erased object), attach to it. Only the model object’s own relations (a relation is on its local ends’ _outgoing/_incoming: see Relation.validate()) are looked at, through the view’s index: not every object in the view, which made adding many objects take the square of the time.

Parameters:

vo (VObject)

Return type:

None

SHOW_ALL_MAX = 2000¶

The most objects showAllModel() shows (by default: see the “gui/ShowAllMax” preference): a model with more to show is shown by its types instead (see showTypes()). (A view of 1000 objects takes a few seconds to make; of 10,000, minutes.)

showAllModel()¶

Show all the model’s objects that aren’t in the view yet, on a grid – or, if there are more than SHOW_ALL_MAX, just its node types (see showTypes()), to be expanded as they’re wanted. The variables go into the windows they belong in (see homeStrays()), and what’s landed in a window it doesn’t belong in is pushed out (see bumpIntruders()).

showTypes(arrange=True)¶

Show just the model’s node types – its own and its super-models’ (eg: an ontology it’s built on: see layout.nodeTypes()), but not the system’s – with the isa links between them, arranged as a tree, by isa, growing down (see treeLayout.TreeLayout): for a model too big to show all at once (see showAllModel()). Each type can be expanded to bring in its instances, as they’re wanted.

Parameters:

arrange (bool) – Whether to arrange them (as a tree): if not, they’re all in one place.

Returns:

The types.

Return type:

list[Node]

search(pattern, wholeWord=False, matchCase=False, regex=False, wholeModel=False, superModels=False, confirm=None)¶

Highlight the nodes and relations in the view whose names match pattern (see sn.model.model.nameMatcher()) – not isa links, nor those not drawn just now (see VObject.isHidden()) – replacing any earlier highlights, and scroll to show them. With wholeModel, those in the model (and, with superModels, its super-models) that aren’t in the view are shown first (one undoable command: see represent()), even if they’re in a hidden or erased category; and so are any of those in the view in such a category.

Parameters:

  • pattern (str) – What to look for in names.

  • wholeWord (bool) – See nameMatcher().

  • matchCase (bool) – See nameMatcher().

  • regex (bool) – See nameMatcher().

  • wholeModel (bool) – Look in the model too, and show what’s found.

  • superModels (bool) – With wholeModel: in its super-models too.

  • confirm (Callable[[int], bool] | None) – With wholeModel: asked, with how many objects would be shown, whether to show them (eg: there are a lot); None: they are.

Returns:

The view objects highlighted, and how many were shown.

Return type:

tuple[list[VObject], int]

Raises:

re.error – If regex and pattern isn’t a good regular expression.
