sn.model.prologReasoner module¶

A Reasoner engine built on SWI-Prolog (Prolog, with tabling), through its Python interface, janus (pip install janus-swi, imported as janus_swi: it needs SWI-Prolog 9.1.12 or later installed).

The engine-neutral facts from Reasoner.facts() are rendered as Prolog facts, the rule base in prologReasoner.pl (a port of clingoReasoner.lp) is applied, and the results are mapped back onto the model’s GraphObjects. Every GraphObject is an atom '#N'.

Prolog’s tabling, with the well-founded semantics, does what clingo’s grounding does: recursion ends, and a negation is evaluated once what it tests is known – so a rule’s negated attribute test (“not gender: female”) is about the attributes the rules conclude too, as for clingo. (If rules make a loop through a negation, so that what they conclude can’t be decided, what depends on it is left out.)

Each run loads the rule base, the facts and the rules into a module of its own, which goes when it’s done (see _HELPER). Prolog is called from one thread (see _call()), whatever thread asks.

sn.model.prologReasoner._HELPER = "\n:- module(sn_janus, [sn_run/4]).\n% Loads a program (text) into a module of its own, and reads the true answers\n% of some of its predicates: see PrologReasoner._solve().\n\n:- dynamic sn_error/1.\n:- multifile user:message_hook/3.\n\n% While a program loads and runs: its errors are kept (to be raised in Python),\n% and its warnings (eg: singleton variables) aren't printed.\nuser:message_hook(Term, Kind, _) :-\n    nb_current(sn_quiet, true), !,\n    ( Kind == error -> sn_text(Term, S), assertz(sn_error(S)) ; true ).\n\nsn_text(Term, S) :-\n    catch(( '$messages':translate_message(Term, Lines, []),\n            with_output_to(string(S0), print_message_lines(current_output, '', Lines)) ), _, fail), !,\n    S = S0.\nsn_text(Term, S) :- term_string(Term, S).\n\n% sn_run(+Text, +Preds, -Results, -Errors): Results is a list of Pred-Rows, a\n% row a list of the arguments of a true answer (as Python can have them: see\n% sn_py/2); or Errors, a list of messages.\nsn_run(Text, Preds, Results, Errors) :-\n    retractall(sn_error(_)),\n    setup_call_cleanup(nb_setval(sn_quiet, true),\n        catch(in_temporary_module(M, true, sn_load(M, Text, Preds, Results0)), Ex,\n              ( sn_text(Ex, S), assertz(sn_error(S)), Results0 = [] )),\n        ( nb_setval(sn_quiet, false), abolish_all_tables )),\n    findall(S1, sn_error(S1), Errors),\n    ( Errors == [] -> Results = Results0 ; Results = [] ).\n\nsn_load(M, Text, Preds, Results) :-\n    setup_call_cleanup(open_string(Text, In),\n        load_files(M:sn_program, [stream(In), silent(true)]),\n        close(In)),\n    ( sn_error(_) -> Results = []\n    ; ( current_predicate(M:sn_close/0) -> M:sn_close ; true ), % (see prologReasoner.pl)\n      maplist(sn_rows(M), Preds, Results) ).\n\nsn_rows(M, P, P-Rows) :-\n    findall(Row, ( current_predicate(M:P/N), functor(G, P, N), call_delays(M:G, true),\n                   G =.. sn.model.prologReasoner._ordered(body)¶

body (a rule’s literals), in the order Prolog should run them. Prolog runs a body in order: a literal that shares no variable with those before it multiplies their answers (eg: data(X), data(Y), data(Z) before the relations between them), and a test (\==) or a negation must wait until what it tests is bound. So, as for CLIPS (see sn.model.clipsReasoner._ordered()): first a literal with a constant, then each that shares the most with those already run – and each test, and each negation, as soon as the variables it tests are bound (a variable that’s only in a negation is its own).

Parameters:

body (list[str])

Return type:

list[str]

class sn.model.prologReasoner.PrologReasoner(model, rules=PosixPath('/Users/kremer/git/semanticNets/src/sn/model/prologReasoner.pl'), showSysRules=None)¶

Bases: Reasoner

Native queries are extra Prolog clauses defining an answer predicate (ans by default) over the fact vocabulary and the rule base’s results (holds/3, isa_star/2, inherited/3, …), as for clingo. Strings are written in double quotes. Eg:

r.query('ans(X) :- name(F,"fred"), name(T,"owns"), holds(T,F,X).')

A query’s clauses run in the order they’re written (start with what binds the most); a predicate of their own that’s recursive should be tabled (:- table p/2.).
