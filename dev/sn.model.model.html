sn.model.model module¶

This is the base definitions of the Model, its contained objects, GraphObject objects and specializations of these:

  • Node

    • Collection

      • AllModelCollection

  • Relation

    • IsaIndividual

Models “live” in memory (util.persistence.pRef.PRDb.AllDbs) because one model can be shared by any number of views in the process. However, models don’t know about views (though views obviously know about models) and comminicate with views only indirectly as Subject calling the the upddate() method of an Observer in an Observer design pattern.

The various subtypes of GraphObject model a typed graph of objects in higher order logic (“higher order logic” because also relations participate in the type hierarchy). A subtype of Relation called IsaIndividual is necessary to implement special behaviour to prevent endless recursion as isa is defined in terms of itself.

Node is a simple subclass of GraphObject, but acts as the superclass to Collection which forms the embodiment of subgraphs such as queries, rules, and definitions in the logic.

isPatternElement(_seen=None)¶
Parameters:

_seen (set[int] | None)

Returns:

True iff this object describes a pattern rather than the world – it’s then not data: the reasoner doesn’t take it as a fact, and getRelatedTo() etc. leave it out. That is:

  • a variable (see isVariable()), or

  • a relation contained by a collection that quotes what it contains (see quotesContents(): a context, eg: a rule, query or constraint) – the target of a relation that isa “contains” (eg: a rule’s antecedent or consequent) – or

  • a relation with a pattern element at either end (eg: ?x -parent-> ?y, or ?x’s isa link).

The “contains” relations themselves are real (“this rule contains that”), unless contained in turn. Constants in a pattern (eg: fred) are real too: they’re just what its relations connect. So is what a plain collection contains (eg: a Rep Plus box): it’s a box of facts, not of patterns.

Return type:

bool

parts(relationType=None)¶

A part is a plain context (an individual of the SN type context) that a box holds by a relation of an SN subtype of contains other than contains itself – antecedent, consequent, definiendum, definiens, condition or required (or an SN subtype of one of those, or another such relation type): what the part holds is the graph, and the relation’s SN type says what the graph is to the box. Eg: a rule holds a context by an “antecedent” relation, and the context holds the antecedent’s nodes and relations by “contains” relations. A rule may have several antecedents: it then fires when any one of them matches (see sn.model.reasoner.ruleSpecsOf()).

(Files written before parts held what’s in them directly: rule -antecedent-> ?x. They’re converted as they’re read: see Model._migrateRuleParts(). The reasoner still reads that shape, eg: in a model that can’t be changed, as part of the first part of that SN type.)

connect(source=None, destination=None)¶

Connects or re-assigns the src and/or dst links by removing any existing links and setting the pointers in both this Relation and the target GraphObjects.

Note

Use this method during Relation construction or when modifying the source and/or destination of the Relation. This method ONLY applies to Relations. (contrast GraphObject._disconnect() and GraphObject._reconnect())

Observers are told of each end it changes (see _endpointChanged()), as the src and dst setters tell them – but not while the relation’s being made, or its model read.

Parameters:

  • destination (GraphObject | None) – The GraphObject for the dst link.
