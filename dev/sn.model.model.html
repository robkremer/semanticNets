sn.model.model module¶

This is the base definitions of the Model, its contained objects, GraphObject objects and specializations of these:

  • Node

    • Collection

      • AllModelCollection

  • Relation

    • IsaIndividual

Models “live” in memory (util.persistence.pRef.PRDb.AllDbs) because one model can be shared by any number of views in the process. However, models don’t know about views (though views obviously know about models) and comminicate with views only indirectly as Subject calling the the upddate() method of an Observer in an Observer design pattern.

The various subtypes of GraphObject model a typed graph of objects in higher order logic (“higher order logic” because also relations participate in the type hierarchy). A subtype of Relation called IsaIndividual is necessary to implement special behaviour to prevent endless recursion as isa is defined in terms of itself.

Node is a simple subclass of GraphObject, but acts as the superclass to Collection which forms the embodiment of subgraphs such as queries, rules, and definitions in the logic.

isPatternElement(_seen=None)¶
Parameters:

_seen (set[int] | None)

Returns:

True iff this object describes a pattern rather than the world – it’s then not data: the reasoner doesn’t take it as a fact, and getRelatedTo() etc. leave it out. That is:

  • a variable (see isVariable()), or

  • a relation contained by a context – the target of a relation that isa “contains” (eg: a rule’s antecedent or consequent) – or

  • a relation with a pattern element at either end (eg: ?x -parent-> ?y, or ?x’s isa link).

The “contains” relations themselves are real (“this rule contains that”), unless contained in turn. Constants in a pattern (eg: fred) are real too: they’re just what its relations connect.

Return type:

bool
