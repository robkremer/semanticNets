sn.model.constraints module¶

The constraints of pattern variables: what an object must be like to match a variable (eg: ?p) in a query or a rule’s antecedent – or, in a rule’s consequent, what’s concluded about it.

A variable’s constraints are the text of its “constraints” attribute, eg:

alive, age: 30, owner: ?o, nickname: 'Big Al'

  • key alone: has the attribute (any value).

  • key: value: has it with that value. A value is a number, true or false, a value variable (a variable’s name, eg: ?o – see sn.model.names: the same value wherever it’s used in the rule or query), or text – quoted ('...' or "...") if it has commas, colons or quotes in it, or would otherwise read as one of the others.

  • The relational properties (symmetric, asymmetric, reflexive, irreflexive, transitive) are tags on relation types: symmetric means it is, symmetric: false that it isn’t.

  • not before any of these negates it: not alive: doesn’t have the attribute; not gender: female: doesn’t have it with that value (so something with no gender at all passes – gender, not gender: female says it has one, and it isn’t female). There can be more than one for a key (not colour: red, not colour: blue). A negated value variable must also be used without not somewhere in the pattern, which gives it its value. They’re tests: a rule can’t conclude that something isn’t so.

They may be typed with a variable’s name, after :where: – eg: ?p :where: alive, age: 30 – and are then moved into the attribute (see splitWhere()).

sn.model.constraints.CONSTRAINTS_NOTE = 'A variable\'s constraints: what an object must be like to match it (in a query or a rule\'s antecedent), or what\'s concluded about it (in a rule\'s consequent). Separated by commas:\n  alive           has the attribute "alive" (any value)\n  age: 30         has "age" equal to 30 (numbers, true/false, or text: quote it if it has commas, colons or quotes, eg: \'Big Al\')\n  age: ?a         has "age" equal to that of the other constraints using ?a\n  symmetric       (of a relation type) is tagged symmetric; "symmetric: false": isn\'t. Likewise asymmetric, reflexive, irreflexive, transitive.\n  not ...         negates any of these, eg: "not gender: female" (true, too, of something with no gender at all), "not alive". Only as tests: not in a rule\'s consequent.\nThey can also be typed with the name, after ":where:", eg: ?p :where: alive, age: 30'¶

Parameters:
