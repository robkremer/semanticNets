sn.view.graphics.sngContext module¶

The context of a graphical view (SNGContext): the commands a view adds to its model’s (see sn.controller.modelInterface.ModelContext) – moving, resizing, collapsing, showing (representing), erasing, pasting, hiding and expanding its objects – each an undoable command (its own class, inside the context, implements it). Every view (sn.view.graphics.sngView.SNGView) has one.

Created on Oct 18, 2026 (from sngView.py)

Code author: Rob Kremer <robkremer@me.com>

__init__(obj, x, y, _oldPos=None, adjustPos=True, _carry=True, _wasFloating=None, _drag=False)¶
Parameters:

  • adjustPos (bool) – [default=True] Passed to obj.moveTo(): whether to let the local layout heuristic (FindFree) nudge obj off anything it lands on. Moves that must land exactly where computed (eg: gathering outliers) pass False.

  • _oldPos (list[int] | None) – [Optional] The object’s true position before the drag that produced (x,y) began – eg: self.dragInfo[0], self.dragInfo[1], captured in VObject.onButton_1() at mouse-down, before any <B1-Motion> tick has moved anything. If omitted, do() falls back to capturing obj.boundingBox() at do()-time instead, but that’s almost never what you want here: by the time a drag’s do() runs (on button-release, via context.move()), onB1_Motion() has already repositioned obj via direct moveBy() calls that never touch the Command system, so a do()-time capture only ever sees where the drag ended (or, after FindFree has additionally perturbed that via adjustPos(), not even that) – never where the object was before the user picked it up. Passing the true pre-drag position explicitly is what lets a single undo() restore the whole move rather than just its last FindFree-driven leg.

  • _carry (bool) – [default=True] Passed to obj.moveTo(): whether a context window carries what’s inside it along. A move that’s one of many (eg: a layout’s) whose contents are moved by their own commands passes False: otherwise redoing or undoing it would move them twice.

  • _wasFloating (bool | None) – [Optional] For a relation’s label placed by a layout: whether it floated (between its ends) before – the move pins it (it no longer floats), and undoing it puts that back.

  • _drag (bool) – [default=False] Whether it’s the user dropping something they dragged (see VObject.onB1_ButtonRelease()), not a program moving it: eg: a tree layout pins a dragged node where it’s dropped (see treeLayout.TreeLayout.adjust()).

  • y (int | float)

visibility(category, mode='hide')¶

Show, hide or erase a category of objects in the view (see SNGView.categories). Hidden objects stay in the view, just not drawn; erased ones are taken out of the view (not the model). Either way, expand won’t bring in more of them.

Parameters:

  • category (str) – The category’s name, eg: “types”, “isa individuals”.

  • mode (str) – “show”, “hide” or “erase”.
