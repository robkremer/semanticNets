class sn.view.graphics.vobjects.VObject(view, modelObject, shape='Rectangle', x=None, y=None, x1=None, y1=None, **kwargs)¶

Bases: AGObject[SNGView, VRelation], Observer, Dirtyable, ErrorReportingObject

An object that visually represents some object in a tygra Model that resides in a particular SNCanvas (which may include VObjects representing objects in several different tygra Model objects).

The “size” and location of VObject considered to be that of the self._shape object, which in turn is controlled by the self.boundingBox() method. Note that decorators may be drawn outside of this bounding box.

BATCH_PLACED = 20¶

The most new nodes an expansion has the view’s dynamic layout place one by one (see expand()): more are placed all at once.

expand(filter=<function VObject.<lambda>>, expand=0, _done=None, _exempted=None)¶

Show this object’s relations that aren’t shown yet (and so what’s at their other ends) – and, if expand > 0, expand each object at the other end of each of its relations (shown already or not) in turn, by expand - 1. So 0 shows this object’s neighbours, 1 their neighbours too, and so on.

What it brings in is placed by the view’s dynamic layout, if it has one (see SNGView.localLayout), once it’s all made: up to BATCH_PLACED nodes one by one, as anything new is (see SNGView._placeNew()); more all at once – the nodes (see layout.LayoutHeuristic.placeBatch()), then, once they’re put between their ends, the relations’ labels (see layout.LayoutHeuristic.placeLabels()). One by one, each is placed clear of everything placed before it, which for thousands takes minutes.

Parameters:

  • filter (Callable[[Any, Relation], bool]) – Optional[Callable[[Self, Relation], bool]] A function selfxRelation->bool where that relation will only be expanded if the function returns True

  • expand (int) – [Optional[int], default=0] The number of hops to expand beyond this object’s neighbours.

  • _done (dict[int, int] | None) – (Internal) The objects expanded so far in this expansion (by id()), and by how many more hops: none is done twice to the same depth or less, as an expansion would otherwise grow exponentially with the depth (going back and forth along each relation, round each cycle).

  • _exempted (list | None) – (Internal) If filter has a true “showsHidden” (see expandDialog.choiceFilter(): relation types asked for by name), the relations it follows are followed even in a hidden or erased category, and they and what they lead to are shown anyway (see SNGView._exemptIfFiltered()): each one shown so is added to this, so it can be hidden again (eg: on an undo).

_reconnect(**kwargs)¶

Reconnect this disconnected object to it’s Model by:

  • reregistering it to the Model

  • reregistering (to other objects) the far ends of the relations

  • reregistering all the above relations with the Model

Note

This method should only be used to undo a _disconnect() operation.

Note

A relation r connecting two objects that are both being reconnected together (eg: a multi-selection undo of an erase, where r itself was one of the erased objects) gets reconnected as a side effect of whichever of the two objects is processed first: that object’s own r._reconnect(kept=self) call both registers r and re-appends it onto the other (not-yet-reconnected) object’s _incoming/_outgoing list, so that object sees r again once its own turn comes. Guarding with r._isConnected() below – mirroring the #TODO on _disconnect() about chains of transitive relations – is what keeps that second encounter from trying to reconnect (and re-assert) an already-reconnected r.
