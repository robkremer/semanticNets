sn.model.names module¶

The grammar of object names: which names are constants and which are variables – and of which kind. This is the only place that knows the syntax: everything else asks grammar (see NameGrammar.parse()), so an application that needs its own syntax for names can install its own grammar (see setGrammar()).

The default grammar:

fred

a constant: names the object it is

?x

an individual variable: matches individuals

^T

a type variable: matches types

!a

an “any” variable: matches individuals and types alike

A variable used as a relation’s type (eg: ^r in !a -^r-> ?b) matches relation types, whatever its kind (an individual can’t be a relation’s type).

A variable whose stem starts with “_” (eg: ?_brother, or just ?_) is hidden: it matches as any other does, but a query’s answers don’t report it (see isHiddenName()): eg: ?x -has-brother-> ?_b answers who has a brother, not who it is.

class sn.model.names.NameGrammar¶

Bases: object

The default grammar of names (see the module doc). To change the syntax, subclass it, override parse() (and describe(), which says it in words), and install an instance with setGrammar().

The base rules (see sn.model.reasoner.BASE_RULES) are written in the default syntax (eg: !a -^r-> ?b), so a replacement should extend it rather than drop it: leave the names it doesn’t claim to super().parse().

PREFIXES: dict[str, NameKind] = {'!': NameKind.ANY, '?': NameKind.INDIVIDUAL, '^': NameKind.TYPE}¶
