sn.view.graphics.sourceWindow module¶

Showing a file at a line – eg: a class or function’s source (see pythonParser) – in the user’s editor, or, failing that, in a read-only window of its own here (SourceWindow).

The editor is the “gui/editorCommand” preference: a command, with {path}, {line} and {url} (the file’s file: URL, for URL schemes) in it – eg: bbedit +{line} {path}. It’s split into words as a shell would (quotes keep a word together; on Windows, a backslash is just a backslash), each word filled in, and run without a shell: so whatever’s in the path, it’s only ever the file to open (and never an option: it’s always an absolute path). Empty, or if it can’t be run, the built-in window’s used.

Eg (and see the preference’s note, in sn.PREFS): for an Eclipse that’s running, on a Mac – its launcher would start another, which finds the workspace in use – an AppleScript sends it the file as “path:line”, which Eclipse takes apart (giving its own app’s path; the first time, macOS asks whether this may control Eclipse):

osascript -e "on run a" -e "tell application \"/Applications/Eclipse.app\" to open (POSIX file (item 1 of a))" -e "end run" {path}:{line}

Parameters:

  • template (str) – The command (see the module doc).

  • line (int) – The line (1-based).

Returns:

The command’s words, filled in (see the module doc).

Return type:

list[str]

Raises:

EditorCommandError – If it’s malformed: eg: an unclosed quote, a “{” that isn’t one of {path}, {line} or {url} (use “{{” for a “{“), or it’s empty.

sn.view.graphics.sourceWindow.showSource(path, line=1, end=None, parent=None)¶

Show path in a SourceWindow – the one it’s already in, if there is one, read afresh – at line, with lines line to end highlighted.

  • end (int | None) – The last line to highlight; default: line.

Returns:

SourceWindow | None
