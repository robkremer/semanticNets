sn.view.graphics.viewFiles module¶

A graphical view’s files, window menus and locking (FilesMixin): one of the parts of sn.view.graphics.sngView.SNGView (see viewBase).

Created on Oct 18, 2026 (from sngView.py)

Code author: Rob Kremer <robkremer@me.com>

class sn.view.graphics.viewFiles.FilesMixin¶

Bases: ViewBase

A view (sn.view.graphics.sngView.SNGView) and its files: saving it and its model (as, or a copy), the model’s super-models (replacing one, opening one’s view) and preferences, closing the model; the items it puts in the application’s menus while its window has the focus; and locking it so it can’t change its model.

doSaveView()¶

Save this view. This is the target the “File | Save view” menu item (added/removed by onWindowFocusIn()/onWindowFocusOut() below) is wired to while this view’s window is focused – kept as its own method (rather than wiring the menu straight to save()) since Rob’s planning sibling “Save model”, “Save view as…”, “Save model as…” commands here too, and this is the natural place for any save-view-specific behavior (confirmation, status message, …) if/when it needs more than a plain save.

Return type:

None

doSaveModel()¶

Save this view’s model: the target of the “File | Save model” menu item (added/removed like “Save view”: see onWindowFocusIn()). Not a model that’s write-locked (eg: the system model).

Return type:

None

_saveCopy(what, db, extension, filetypes)¶

Ask for a file, and save a copy of db (this view, or its model) there. This window stays on the original – not as a Mac “Save As” does – so say so, in the log, and flash the terminal pane to draw attention to it.

Parameters:

  • what (str) – “view” or “model”, for the messages.

  • db (SNGView | Model) – The view or model.

  • extension (str) – Its files’ extension, eg: “.snv”.

  • filetypes (list[tuple[str, str]]) – For the file dialog.

Return type:

None

doSaveViewAs()¶

Save a copy of this view in another file: the target of “File | Save view as…” (see _saveCopy()). This window stays on this view.

Return type:

None

doSaveModelAs()¶

Save a copy of this view’s model in another file: the target of “File | Save model as…” (see _saveCopy()). This window stays on the model.

Return type:

None

doChangeModel()¶

“File | Change model…”: show another model in this view – eg, a copy of its model, or the one it was moved to (see Application.changeModel()): its objects show the objects with the same ids in it. Its unsaved changes are saved first, or lost, as the user says: it’s read again from its file.

Return type:

None

static _afterFileMenu()¶
Returns:

The menu bar position just after “File” (where “Edit” goes).

Return type:

int

doReplaceSuperModel()¶

“Edit | Replace super-model…”: put another model in place of one of this view’s model’s super-models – or of a model its objects refer to that isn’t one (see Model.unlistedModels()) – eg: an ontology’s copy on the web in place of the local one (see Model.replaceSuperModel()); and show the same objects of the new one in its open views.

Return type:

None

doModelPreferences()¶

“Edit | Model preferences…”: edit this view’s model’s preferences (see sn.model.modelPrefs) – just their values (their notes are their names’ tooltips). Its super-models are shown as its superDBs are (see Model.superModelPaths()), “Add file…” choosing a model file, “Add URL…” taking its URL (eg: on the web: see askModelURL()), and set from the edited list (see Model.setSuperModels()): if that can’t be done, nothing is changed, and the reasons are shown.

Return type:

None

doCloseModel()¶

Close this view’s model: the target of the “File | Close model” menu item (added/removed like “Save view”: see onWindowFocusIn()). See Application.closeModel().

Return type:

None

onWindowFocusIn()¶

This view’s AppWindow just gained focus – add (or, if already present from some other cause, replace) the “File | Save view” menu item so it’s wired to this view’s doSaveView().

Called by AppWindow._onWindowFocusIn(). Since only one AppWindow is ever focused at a time, and each focused window’s SNGView calls this on the way in, this is enough to guarantee “Save view” always targets whichever view the user is actually looking at – no shared “currently active view” bookkeeping needed anywhere else.

Return type:

None

onWindowFocusOut()¶

This view’s AppWindow just lost focus – or is being closed outright – so withdraw the “File | Save view” menu item.

Called by AppWindow._onWindowFocusOut() (via _checkStillActive()) when focus genuinely leaves this window, and by Application._closeWindow() when this window is closed (which isn’t guaranteed to first fire a Tk focus-out event). Safe to call even if this view never added the item (e.g. its window was never focused) – removeFromMenuBar() is a no-op in that case.

Return type:

None

SN_VIEW = 'sn.snv'¶

The file name of the system model’s (sn’s) view, in the sn.model package’s folder: sn has no file of its own, so it’s taken to be there – with the base rules (see superModelView()).

_superModelsMenu()¶
Returns:

The “File | Open super model” cascade: an item for each of this view’s model’s super-models (see superModelView()), nearest first.

Return type:

Menu

superModelView(model)¶

Where a super-model’s view goes: next to its file, with the same name and “.snv” – for the base rules, next to the file they come from (see sn.model.reasoner.baseRulesSource()), not the copy they’re read from; for the system model (sn), which has no file, in the sn.model package’s folder (see SN_VIEW).

Parameters:

model (Model) – A super-model.

Returns:

(the URL of the model’s file – or “” for sn, which has none – and the URL of its view).

Return type:

tuple[str, str]

openSuperModel(model)¶

Open a window on one of this view’s model’s super-models (see superModelView()): its view, if it has one, or else a new one – for the base rules, of the file they come from (read-only).

Parameters:

model (Model) – The super-model.

Return type:

None

isModelEditor()¶
Returns:

Whether the model can be changed in this view: it isn’t locked (see setEditLocked()), and the model isn’t write-locked. Either way, the view itself can be (eg: moving things, or erasing them from view).

Return type:

bool

lockedReason()¶
Returns:

Why the model can’t be changed in this view (see isModelEditor()), for a message.

Return type:

str

editLocked()¶
Returns:

Whether the user’s locked this view, so it can’t change the model (see setEditLocked()).

Return type:

bool

_editLockedVar()¶
Returns:

Whether the model can’t be changed in this view (see isModelEditor()) – what “Edit | Lock view” shows (and sets: see _onLockViewItem()).

Return type:

BooleanVar

_onLockViewItem()¶

“Edit | Lock view” was chosen: lock or unlock the view, as the pencil in the reasoning toolbar does (see setEditLocked()) – not a write-locked model’s.

Return type:

None

setEditLocked(locked=True)¶

Lock this view, so it can’t change the model (see isModelEditor()) – only how it’s shown – or unlock it. Not other views of the model. It’s saved with the view. A write-locked model’s view can’t be unlocked.

Parameters:

locked (bool)

Returns:

Whether it’s done (unlocking a write-locked model’s view isn’t).

Return type:

bool
