sn.model.reasoner module¶

The engine-independent interface to back-end reasoners for Model objects.

A reasoner engine subclasses Reasoner (see sn.model.clingoReasoner.ClingoReasoner). What is shared here:

  • Reasoner.facts() exports the model as engine-neutral facts. Their vocabulary is the contract every engine reasons over:

    obj(O)

    every GraphObject (including those of super-models)

    individual(O)

    GraphObject.isIndividual()

    kind(O,K)

    K in top, node, relation, isa

    collection(O)

    O is a Collection (also of kind node)

    name(O,S)

    GraphObject.name

    const(K,O)

    well-known objects: top, relation, isa, node, …

    parent(X,P)

    GraphObject.getParents() (incl. implicit defaults)

    lsrc(R,C), ldst

    locally set relation endpoints (Relation.localSrc/.localDst)

    domain(T,C), range

    the signature of relation type T (Relation.domain/.range)

    src(R,S), dst

    effective endpoints (Relation.src/.dst, inherited)

    link(R,S,D)

    individual, non-isa relation R with both endpoints

    prop(T,P)

    relation type T is tagged with P (reflexive, irreflexive, symmetric, asymmetric, transitive)

    member(C,M)

    M is a member of box C: a collection (of any Python class) that doesn’t quote what it contains (see GraphObject.isCollection(), quotesContents())

    attr(O,K,V)

    effective non-“vis/” scalar attributes

    lattr(O,K)

    O has attribute K locally

    card(T,Dir,Min,Max)

    relation type T’s cardinality: each source (Dir out) or destination (in) has Min..Max others by T (Max -1: any number). See CARDINALITY.

    card_error(T,K,M)

    T’s cardinality attribute K can’t be read: message M

    pattern(X)

    X describes a pattern (in a rule etc.), not the world (see GraphObject.isPatternElement())

    var_kind(X,K)

    X is a variable over K: individual, type or any (see GraphObject.variableKind() and sn.model.names)

    def_part(C,D,I,A,P,Pol)

    node C is defined by its links (see DEFINING): D is meet or join; its Ith (from 1) defining link is to A (from A, for a join); P is the relation it requires; Pol pos if P is the order (neg if not)

    def_last(C,D,N,Q,R)

    C has N such links; Q is the order; R the tagged relation type (the first link’s)

    def_marks(C,D,TK,FK,V)

    their truth attributes: true’s and false’s keys, and the value concluded

    def_mixed(C,D)

    one of the links’ other ends has both (locally)

    def_world(C,D,NV,DV)

    C’s links are explored, in worlds (see DEFINING): NV is the value of the marks every world has, DV the value of those every preferred world has

    def_prefer(C,D,P)

    … and their ends are preferred by P (a relation type: A -P-> B, A yields to B)

    def_rank(C,D,K)

    … and C’s preferences come Kth from last (the highest K first: see DEFAULT_ORDER)

  • Inferences and Violation are what every engine returns, and the violation codes (see _MESSAGES) are shared.

  • The typed queries (Reasoner.related(), Reasoner.isa(), …) work with any engine. Reasoner.query() is the engine’s native query language (see Reasoner.language), and so is not portable.

The semantics every engine must implement are pinned down by test/test_model/test_reasoner.py: an engine is conforming if it passes ReasonerSpec.

The Model remains the single source of truth: reasoners never modify it.

sn.model.reasoner.PROPERTIES = ('reflexive', 'irreflexive', 'symmetric', 'asymmetric', 'transitive')¶

The relational properties, which are tags on specific relations.

sn.model.reasoner.CARDINALITY = {'cardinality': 'out', 'inverseCardinality': 'in'}¶

The cardinality attributes of a relation type – like the relational properties, its own (not inherited by its subtypes): how many objects each source is related to by it (or by its subtypes: a father is a parent), and how many each destination is related from. Eg: has-father’s “cardinality” “1..1” (everyone has exactly one father), has-parent’s “2..2”, has-child’s “0..*”, a desk’s has-desk “inverseCardinality” “0..1” (no desk is two people’s). See parseCardinality() for how they’re written, and clingoReasoner.lp for what they mean: too many different (named) objects is an error and too few (for the domain’s individuals: the range’s, for “in”) a warning; at most one makes the objects the rules invent the same object (as each other, or as a named one); and exactly one invents one where the model has none.

sn.model.reasoner.DEFINING = {'join': 'in', 'meet': 'out'}¶

The attributes of a relation type that make its links define a node (Gaines’s structural connectives: his iterative clause), and which of the node’s links they are: its own (out), or those to it (in). Unlike the relational properties, they’re inherited by the type’s subtypes (a subtype of a conjunct link is one). The value is the name of a relation type, P (the relation its links require); and the type can also have:

  • order: the name of the order relation (Q) the node is defined in (P if it hasn’t): taken to be reflexive – everything is ordered before itself.

  • trueMark, falseMark, markValue: truth attributes’ keys, and the value to conclude (see below).

  • necessaryValue, defaultValue, prefer: with the truth attributes, explore the node’s cases (see below): the values to conclude for what every world has, and for what every preferred world has (necessaryValue, if it hasn’t); and the name of the relation type that says which of its links’ other ends are preferred.

A node C with (asserted) meet links to A1..An is their meet: whatever has P to each Ai (Pi, each link’s own) has Q to C – eg, with P and Q includes, whatever includes every conjunct includes the conjunction. A link whose P is Q is positive (C -Q-> Ai: the link is a Q, as a conjunct includes), and its Ai counts as having Q to itself; any other is negative (eg: a conjunct excludes, whose P is excludes). And dually, a node D with join links from A1..An is their join: D has Q to whatever each Ai has Pi to. (A node that has no such links isn’t defined: nothing is concluded about it.)

With truth attributes (trueMark, falseMark: eg, the KNet rules model’s markTrue and markFalse), a defining link holds when its other end has trueMark (or falseMark, if it’s negative), and fails when it has the other; and so (Belnap’s four values: a node may have both):

  • a meet has trueMark (the value markValue) when all its links hold, and a join falseMark when all of them fail;

  • a meet that has falseMark, all of whose links but one hold, makes that one fail (its end gets the mark that does that); and a join that has trueMark, all of whose links but one fail, makes that one hold – unless one of its links’ other ends was given both marks (it’s inconsistent: as KNet does, that blocks disjunctive syllogism, and its dual). That’s the asserted (local) marks: one that both its marks were concluded for doesn’t block it (it would take negation through the marks’ own propagation).

(That a link’s failing makes a meet false, and its holding a join true, is just what the links themselves are: eg: a conjunct includes is an includes.)

With necessaryValue too, a true join none of whose links hold (and a false meet none of whose links fail) is explored, as KNet’s Explore does: each of its links that doesn’t fail (doesn’t hold) is a case – a world in which it holds (fails) – and so is each case of the nodes that makes true (false), and so on; a world in which a node gets both marks that didn’t have them both already is incoherent, and isn’t one. What every world has, the node has: with necessaryValue (eg: a join of A and B, each of which includes C, makes C true). And with prefer, the links’ ends are preferred (Gaines’s preferences, KNet’s normal defaults): in each world, a link whose end yields to (has prefer to) one that doesn’t fail fails itself, and (dually) one that yields to one that doesn’t hold, in an explored meet, holds – and the preferred worlds are those whose preferred ends fail (hold) least, node by node, in the order of DEFAULT_ORDER, the first first. What every preferred world has, the node has: with defaultValue. (What every world has isn’t the default too: it’s necessary.) So far just the clingo engine explores.

The engines conclude these as the tagged relation type’s: fired and rule_attr with it as the “rule”. See Reasoner._definingFacts() for the facts they get.

sn.model.reasoner.DEFAULT_ORDER = 'defaultOrder'¶

The attribute of a defined node (see DEFINING) that says when its preferences come: those whose value is less first (the value is a number: none is 0), and otherwise in the order the nodes are in the models – as KNet takes them in the order they’re in the net (the user can sort them).

class sn.model.reasoner.ReasoningScope(everything=False)¶

Bases: object

Which of a model’s reasoning results are shown – put in the model (see materialize()), marked on its objects and reported: everything, after a whole “reason”; or what’s about the objects reasoned about (see reason()’s about), less what’s about those retracted (see retractReasoning()).

Something is about an object (see Inferences.restricted()) if the object takes part in it: a relation’s ends and type, the rules that concluded it, a violation’s objects, a new object’s match, types and relations – or, for an individual relation, if it’s between the same two objects (eg: reasoning about ann -has-parent-> bob shows ann -has-ancestor-> bob, and bob -has-child-> ann).

The last say wins: something about two objects, one reasoned about and the other retracted, is shown if the first was reasoned about after the other was retracted, and not if it was before. Reasoning about the whole model again starts afresh: everything’s shown.

The relations that the rest of the model implies: each, in turn, is left out (as if it weren’t in the model: see facts()) and the model reasoned over, and it’s redundant if its types still hold between its ends. _finish(ret)¶

What every engine does with its results, before returning them from run():

  • A violation is reported once per set of objects it’s about: eg: an asymmetric relation between a and b once, not again for b and a. (Of such, the one whose args come first in the models’ order is kept.)
