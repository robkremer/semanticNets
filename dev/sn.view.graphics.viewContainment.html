sn.view.graphics.viewContainment.homePane(panes, center, *, says=None, used=None)¶

Which pane of its window (see homeWindow()) something belongs in. In a window with one pane, that. Else, if the window contains it (says): the pane its containment says (antecedent, consequent, …) – the one it’s in, if it says both – or, for a plain “contains”, the one it’s in (or the nearer). If the window’s contents only use it (used): the side they use it on, or astride the divider (BOTH_PANES) if they use it on both (or somewhere not in a pane).

  • used (Collection[str | None] | None) – If it doesn’t: the panes in which the window’s contents use it (None: not in a pane).

Returns:

The pane’s name, or BOTH_PANES.

sn.view.graphics.viewContainment.containmentMove(panes, old, *, target, contained, windowMove=None, endCentres=None)¶

What moving something does to a window’s containment of it: landing in the window (the innermost one there: see windowAt()) puts it in; leaving the window takes it out; and containment of something that was outside the window (eg: out in the “real world”, with its contains arc showing) is left alone, as is a window it neither was nor is in.

A relation dragged along by its ends (endCentres) says little by where its label is: it’s put in only if both its ends are in the window, and taken out only if neither is (so moving ?x in a rule doesn’t pull in its isa link to a type outside).

Parameters:

  • panes (Mapping[str, Sequence[float]]) – The window’s panes, by name (where it is now).

  • old (Sequence[float] | None) – Its centre before (a relation’s: its label’s), or None if it’s new.

  • target (bool) – Whether the window is the one it’s landed in.

  • contained (bool) – Whether the window contains it now.

  • windowMove (tuple[Sequence[float], Sequence[float]] | None) – If the window moved too: its centre (before, after) – whether it was in the window is judged by where it was relative to it.

  • endCentres (Sequence[Sequence[float]] | None) – If it’s a relation dragged along by its ends: their centres.

Returns:

“in” (to be contained by the pane it’s landed in: the caller checks it isn’t already), “out” (no longer contained), or None (left be).

Return type:

str | None

class sn.view.graphics.viewContainment.ContainmentMixin¶

Bases: ViewBase

The context windows of a view (sn.view.graphics.sngView.SNGView): rules, definitions, queries and constraints drawn as windows holding what they contain. Where each thing belongs (its window and pane), keeping out of windows it doesn’t belong in (bumping it out), stacking windows, what’s dropped into or dragged out of one (and the “contains” relations that go with it), and gathering what belongs in a window into it.

Return type:

list[VObject]

BOTH_PANES = 'both'¶

The pseudo-pane (see containmentHomes()) of something a rule or definition uses on both sides: astride the divider.

containmentHomes(among=None, window=None)¶

Where each contained object belongs: the context window, and its pane (see VObject.panes()), that it should sit in – what layouts keep it in (see homeRect()).

What a context contains directly – nodes, relation types, and relations (their labels) – belongs in it. So do the variables a contained relation uses but the context doesn’t contain itself: its ends (eg: the base rules’ !a and !b) and its type (?r). An object contained by (or used in) more than one context (eg: by a rule and by another window on the rule) belongs in the innermost one whose pane it’s in, or, if it’s in none, the smallest (the innermost, if they’re nested). A window belongs only in a bigger window (so nesting can’t go round in circles).

In a rule or definition, the pane is the one its containment says (antecedent, consequent, definiendum, definiens) – the one it’s in, if it’s in both – or, for a plain “contains”, the one it’s in (or nearer). A variable used on both sides belongs astride the divider (BOTH_PANES).

And a relation the context doesn’t contain, whose two ends both belong in the same window, belongs there too (eg: a pattern relation’s isa link to its type variable, !a -^r-> !b to ^r): in its ends’ pane – or, if they’re in different ones, the one that isn’t astride the divider, or astride it if neither is.

Parameters:

  • among (Iterable[VObject] | None) – Just these view objects (default: all of them).

  • window (VObject | None) – Just what this window contains (and its contents use), as if it were the only one (default: all the windows).

Returns:

Each contained view object: (its window, the pane’s name).

Return type:

dict[VObject, tuple[VObject, str]]

bumpIntruders()¶

Push everything drawn in a context window it doesn’t belong in (see belongsIn(): eg: something a window was dropped on, or uncovered by expanding it, or whose containment was removed) out of it – each the least it takes (see awayFromWindows()), onto a free place if there’s one near. Windows go first (carrying their contents), then nodes, then relations’ labels; a floating label is put back between its ends (see VRelation.reposition()), which keeps it out of windows itself. Done after every command (see ViewDoList), not in the middle of a drag.

Returns:

(object, its box before, after) for each one moved, in order.

Return type:

list[tuple[VObject, list[int], list[int]]]

_updateContainment(oldCenters, draggedAlong=())¶

Bring the contexts’ containment into line with where the objects in oldCenters now sit. Positions are centres (a relation’s is its label’s); oldCenters maps each object to where it was, or None if it’s new. For each object:

  • Landing in a window’s pane (the innermost window, if they’re nested) makes it contained by that pane’s relation type (contains, or a rule’s antecedent/consequent). Switching a rule’s panes swaps the type – unless it’s in both, which only an explicit relation can say.

  • Leaving a window it was in removes that window’s containment of it.

  • Containment of an object sitting outside the window (eg: out in the “real world”, with its contains arc showing) is left alone.

Relations in draggedAlong only moved because an end did, so their labels’ positions say little: one is put in a window only if both its ends are in the window, and taken out only if neither end is. (Otherwise moving ?x in a rule would pull in, eg: its isa link to a type outside.)

Call inside a CompositeCommandMgr, so it’s undone with the move.

Parameters:

  • oldCenters (dict[VObject, tuple[float, float] | None])

  • draggedAlong (Iterable[VObject])

Return type:

None

gatherIntoWindow(w)¶

Move what context window w contains (and the variables its contents use) into it, each into its pane (see containmentHomes()), at a free spot – as near as can be to where it was, if that’s just outside its pane; otherwise set out in rows from the pane’s top left, far enough apart for the labels of the relations between them – as one undoable command. What’s already in its pane stays put, and so does what sits in another window that also contains it. If there’s no room, the window grows downward. A collapsed window is expanded first. Floating relations (their labels) aren’t moved: they follow their ends.

Parameters:

w (VObject) – A context window (see VObject.isContextWindow()).

Return type:

None
