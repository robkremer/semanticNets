sn.view.graphics.viewContainment.relationScope(src, dst, *, srcVariable=False, dstVariable=False)¶

Which box (context) a relation belongs in – its scope – by where its two ends are: the innermost box both are in; or, if there’s none, the global context. Never where its label happens to be: a relation that crosses a box’s border isn’t that box’s (eg: from something in one box to something in another, or out in the world, is the global context’s – or that of the box both boxes are in).

But a variable means something only in its box (its pattern: eg, a rule’s ?x), so a relation from a variable to something outside the variable’s box (eg: ?x isa person, with person out in the world; or ?asker likes dave, in a query) is the variable’s box’s.

  • dstVariable (bool) – Whether its destination is.

Returns:

(the innermost box both ends are in, or None; and the box of a variable end that’s inside that one – the source’s, if both are – or None). The relation’s scope is the second, if there is one, else the first.

class sn.view.graphics.viewContainment.ContainmentMixin¶

Bases: ViewBase

The context windows of a view (sn.view.graphics.sngView.SNGView): rules, definitions, queries and constraints drawn as windows holding what they contain. containmentHomes(among=None, window=None)¶

Where each contained object belongs: the context window, and its pane (see VObject.panes()), that it should sit in – what layouts keep it in (see homeRect()).

What a context contains directly – nodes, relation types, and relations (their labels) – belongs in it. So do the variables a contained relation uses but the context doesn’t contain itself: its ends (eg: the base rules’ !a and !b) and its type (?r). An object contained by (or used in) more than one context (eg: by a rule and by another window on the rule) belongs in the innermost one whose pane it’s in, or, if it’s in none, the smallest (the innermost, if they’re nested). A window belongs only in a bigger window (so nesting can’t go round in circles).

In a rule or definition, the pane is the one its containment says (antecedent, consequent, definiendum, definiens) – the one it’s in, if it’s in both – or, for a plain “contains”, the one it’s in (or nearer). A variable used on both sides belongs in the first, the left one (eg: the antecedent, where it’s matched): nothing’s astride a divider.

And a relation the context doesn’t contain, whose two ends both belong in the same window, belongs there too (eg: a pattern relation’s isa link to its type variable, !a -^r-> !b to ^r): in its ends’ pane – or, if they’re in different ones, the left one.

Parameters:

  • among (Iterable[VObject] | None) – Just these view objects (default: all of them).

  • window (VObject | None) – Just what this window contains (and its contents use), as if it were the only one (default: all the windows).

Returns:

Each contained view object: (its window, the pane’s name).

Return type:

dict[VObject, tuple[VObject, str]]

_updateContainment(oldCenters, draggedAlong=())¶

Bring the contexts’ containment into line with where the objects in oldCenters now sit. Positions are centres (a relation’s is its label’s); oldCenters maps each object to where it was, or None if it’s new. For each object:

  • Landing in a window’s pane (the innermost window, if they’re nested) makes it contained by that pane’s relation type (contains, or a rule’s antecedent/consequent). Switching a rule’s panes swaps the type – unless it’s in both, which only an explicit relation can say.

  • Leaving a window it was in removes that window’s containment of it.

  • Containment of an object sitting outside the window (eg: out in the “real world”, with its contains arc showing) is left alone.

  • A window goes into another only if that’s a plain context (one pane, “contains”): not into a rule, definition or requirement.

A relation (with both its ends drawn) is in the box its ends are both in (see relationScope()), not the one its label’s in: dragging its label only moves it from one pane (or part) of that box to another (eg: from a rule’s antecedent to its consequent); moving an end into or out of a box – or the box it’s in into or out of another – moves the relation into the innermost box both its ends are in now (see _rescope()). Those in draggedAlong only moved because an end did. (A relation with no destination of its own goes by its label: in the window it’s dropped in.)

Call inside a CompositeCommandMgr, so it’s undone with the move.

Parameters:

  • oldCenters (dict[VObject, tuple[float, float] | None])

  • draggedAlong (Iterable[VObject])

Return type:

None

gatherIntoWindow(w)¶

Move what context window w contains (and the variables its contents use) into it, each into its pane (see containmentHomes()), at a free spot – as near as can be to where it was, if that’s just outside its pane; otherwise set out in rows from the pane’s top left, far enough apart for the labels of the relations between them – as one undoable command. What’s already in its pane stays put, and so does what sits in another window that also contains it. If there’s no room, the window grows downward. A collapsed window is expanded first. Floating relations (their labels) aren’t moved: they follow their ends.

Parameters:

w (VObject) – A context window (see VObject.isContextWindow()).

Return type:

None

_gatherPlan(w, which=None, homes=None)¶

Where to put what context window w holds that isn’t in its pane (see gatherIntoWindow()), and how big w must be for it.

Parameters:

  • which (Callable[[VObject], bool] | None) – Just those of them this says (default: all).

  • homes (dict[VObject, tuple[VObject, str]] | None) – containmentHomes(), if the caller has it.

  • w (VObject)

Returns:

w’s box (as expanded, if it’s collapsed: grown, if need be), and (object, its box now, its box there) for each to move – or None if there’s nothing to move.

Return type:

tuple[list[float], list[tuple[VObject, list[float], list[float]]]] | None

holdsOnlyInside(w)¶

Whether what context window w holds must be inside it: a window with more than one pane (eg: a rule’s antecedent and consequent), or whose parts are its panes (see GraphObject.tilesParts()). What its parts hold can’t be shown from outside – the parts aren’t drawn, so neither are their “contains” arcs – and outside, nothing would say which part holds it. (What a one-pane window holds may be out in the world, its arc drawn: eg, a query’s subject.)

Parameters:

w (VObject)

Return type:

bool

misplaced(homes=None)¶

What’s not wholly where it belongs (see containmentHomes()): astride the edge of its window, or of its pane (eg: a rule’s divider), or outside a window it can’t be outside. Each is to be brought wholly into its pane – if it’s a variable (it means something only in its pattern), or its window holds only what’s inside it (see holdsOnlyInside()), or its centre’s in the window (where a drop would have put it), or it’s a relation the window holds because its ends say so (see belongsByEnds(): its label dragged out of the box its ends are in) – or else pushed wholly out of the window, its arc drawn. Not floating relation labels (they follow their ends, kept in their panes: see VRelation.placedLabel()), nor what’s in a hidden or collapsed window.

Parameters:

homes (dict[VObject, tuple[VObject, str]] | None) – containmentHomes(), if the caller has it.

Returns:

Each window’s objects to bring into their panes; and (object, window) for each to push out of the window it’s half in.

Return type:

tuple[dict[VObject, list[VObject]], list[tuple[VObject, VObject]]]

strayVariables(homes=None)¶

The variables outside the window they belong in (see containmentHomes()): a variable means something only in its pattern, so one out on the canvas – eg: put there by “show all”, or a layout – is never where it’s meant to be. Not those of a collapsed or hidden window. (They’re among what keepInPanes() puts back.)

Parameters:

homes (dict[VObject, tuple[VObject, str]] | None) – containmentHomes(), if the caller has it.

Returns:

Each window’s strays.

Return type:

dict[VObject, list[VObject]]

keepInPanes()¶

Leave nothing astride a window’s edge or a divider between its panes, nor outside a window it can’t be outside (see misplaced()): each is put wholly in its pane, at a free spot – nudged in, if it’s near, or else set out in rows, as gatherIntoWindow() would (growing the window if there’s no room) – or, if it may be outside and its centre is, pushed wholly out, the least it takes (see awayFromWindows()). So there’s never any doubt which window, or which side of a rule, holds something. Done after every command (see ViewDoList), with bumpIntruders(), and when a view’s read.

Returns:

(object, its box before, after) for each one moved or resized, in order.

Return type:

list[tuple[VObject, list[int], list[int]]]

tidyWindows()¶

Put what the windows hold wholly in their panes (see keepInPanes()), and push what’s in a window it doesn’t belong in out of it (see bumpIntruders()): eg, when a view saved before either was done (or by a program) is read. Not undoable. (When a view’s read, it’s not a change: it’s not marked changed for it.)

Returns:

Whether anything moved.

Return type:

bool

followPanes(w, old)¶

Context window w has been resized by hand, from old: if it has more than one pane (eg: a rule), what’s in its panes moves across with them, in proportion to its width (the panes share it equally: so each thing keeps its place in its pane, and the divider doesn’t pass over it). Up and down, it stays put – and anything the resize leaves outside its pane is put back in it afterwards (see keepInPanes()).

Parameters:

  • old (Sequence[float]) – Its box before.

  • w (VObject)

Returns:

(object, its box before, after) for each one moved.

Return type:

list[tuple[VObject, list[int], list[int]]]
