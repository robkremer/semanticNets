Getting Started¶

Installing¶

Semantic Nets runs on macOS, Windows and Linux. Download it from the Releases page.

On a Mac¶

It comes as a Mac app, on a disk image. There are two:

SemanticNets-1.0-universal.dmg

For any Mac: Intel Macs with macOS 10.15 (Catalina) or later, and Macs with Apple silicon with macOS 11 (Big Sur) or later.

SemanticNets-1.0.dmg

For Macs with Apple silicon (M1 or later) only, with macOS 11 or later. It’s the same app, but smaller.

Open the disk image, and drag Semantic Nets onto the Applications folder beside it.

The first time you open it, macOS will refuse to open it with a double-click, because it isn’t signed by an identified Apple developer. Instead, Control-click (or right-click) it in Applications, choose Open, and then Open again in the dialog. (Or: System Settings | Privacy & Security | Open Anyway.) After that it opens normally.

On Windows¶

SemanticNets-1.0-setup.exe

An installer, for Windows 10 or later (64-bit). It puts Semantic Nets in the Start menu, and makes .snm and .snv files open in it. (It’s installed for you alone, unless you choose all users.)

SemanticNets-1.0-windows.zip

The same program, to unzip anywhere and run (Semantic Nets.exe).

It isn’t signed either, so the first time, Windows SmartScreen may say Windows protected your PC: choose More info, then Run anyway.

On Linux¶

SemanticNets-1.0-x86_64.AppImage

One file, for 64-bit Intel or AMD Linux with glibc 2.35 or later (Ubuntu 22.04, Debian 12, Fedora 36, and later). Make it executable and run it:

chmod +x SemanticNets-1.0-x86_64.AppImage
./SemanticNets-1.0-x86_64.AppImage

(Ubuntu 24.04 and later need sudo apt install libfuse2t64 for AppImages.) A tool like Gear Lever or AppImageLauncher adds it to the menus, and makes .snm and .snv files open in it. Copy as picture needs xclip (or wl-clipboard, on Wayland).

On Windows and Linux, the keys this guide gives with Command are with Ctrl instead, and Option is Alt; Settings… and Quit are at the bottom of the File menu. Keys and mouse lists every key and mouse gesture (Help | Keys and Mouse).

Starting the program¶

Open Semantic Nets as you would any app, or double-click a model (.snm) or view (.snv) file – or drop one on its icon – to open it.

  • The first time, it puts some example models in Documents/Semantic Nets Examples, and opens them: a family, with a rule, a definition and a query (see Contexts: Rules, Definitions, Queries, Constraints and Requirements), and a small taxonomy of animals (see Animation Layout). Help | Install Example Models puts fresh copies there at any time (eg: those of a newer version), replacing the old ones – and any changes you’ve made to them.

  • After that, it reopens the windows that were open when you last quit, at the same size and place – as they were last saved: changes you chose not to save, and the undo history, are gone – and the model directory, if it was showing. If there were none, it shows the model directory (see Files and Settings).

The Help menu has this guide.

The program keeps its settings in ~/.sn/prefs.xml (see Files and Settings), and its log – worth a look if something goes wrong – in ~/Library/Logs/Semantic Nets (on Windows, %LOCALAPPDATA%\Semantic Nets\Logs; on Linux, ~/.local/state/semantic-nets).

Other ways to run it¶

SemanticNets-1.0.pyz

The whole program in one file, for people who already have Python 3.14 (from python.org). It needs a few more packages, installed with:

python3.14 -m pip install clingo requests urllib3 docstring_parser

Then run it with python3.14 SemanticNets-1.0.pyz [file ...]. (If anything’s missing, it says what.)

From the source

With the project and its companion library pythonUtils checked out side by side (see Overview), two scripts in the project’s top directory start it:

./sng [file ...]

The graphical editor, as above: a window on each file named, or else as when the app starts.

./sn [-m file]

The terminal (text) interface only, on the model file (by default, the one it used last). See The Terminal.

The window¶

Each window shows one view of one model. It has two parts:

  • The canvas, at the top, where the network is drawn and edited.

  • The terminal pane, below it, which shows the program’s messages (eg: the reasoner’s report) and takes typed commands (see The Terminal).

Most things are done from the right-click menus: on an object for things to do with it, and on the background for everything else. The background menu has three submenus – model (making objects, validating), view (what’s shown, zooming, and how it’s arranged) and reasoning.

The menu bar has:

  • File: New… (a new model, or a new view of a model), Open…, Open URL…, Open Recent, Save view (the view of the window you’re in), Save model (its model), Save view as… and Save model as… (a copy of either: see Files and Settings), and Close model (its model, and all the windows on it).

  • Edit: Model preferences… (the window’s model’s own settings, eg: its super-models) and Replace super-model… (see Files and Settings).

  • View: Layout panel (see Arranging a View and Animation Layout) and Reasoning toolbar (see Reasoning).

  • Window: Model Directory (see Files and Settings), and the open windows.

  • Help.

A first network¶

  1. File | New…, and give a name, eg: pets.snv. This makes a model (pets.snm) and a view of it (pets.snv), and opens a window on them.

  2. Right-click the background: model | new subtype of Node, and name it animal. Do it again for dog.

  3. Make dog a kind of animal: right-click dog, make relation to… | isa, then click animal. (The line from dog follows the mouse until you click; Esc cancels.)

  4. Make an individual dog: right-click dog, make new instance, and name it rex.

  5. Make a relation type: background menu, model | new subtype of Relation, and name it likes. Then right-click rex, make relation to… | likes, and click on something rex likes.

  6. Click Reason (▶) on the reasoning toolbar at the bottom of the window (or right-click the background: reasoning | reason). The report appears in the terminal pane, and what the reasoner inferred is shown on the canvas, faded, with dashed lines.

For more – arranging it as a tree as it grows, and letting the reasoner work out what follows – see Worked Examples.

Undo and redo are Cmd-Z and Shift-Cmd-Z; nearly everything can be undone, including moves, layouts and edits. Each window has its own undo history: see The Terminal.

Saving¶

File | Save view saves the view (positions, what’s shown, …), and File | Save model the model. Models are also offered for saving when you quit (you’re asked about each one that’s changed). See Files and Settings.
