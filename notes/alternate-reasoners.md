# Alternate reasoner engines for semanticNets

Everything below comes from reading PyPI metadata, upstream source and docs (2026-11-04) and the engine contract in `src/sn/model/reasoner.py`, `clingoReasoner.py`/`.lp`, `sphinx/source/developer/reasoner.rst`, `test/test_model/test_reasoner.py` and `packaging/`. **Nothing was installed or run**: no wheel was imported, no engine timed, no rule ported. Where a claim rests on that, it says so, and section 5 lists what one real install per platform must confirm.

## Recommendation

**1. Nemo** (`pip install nemo-python`, import `nmo_python`; TU Dresden KBS, https://github.com/knowsys/nemo). An in-process Rust existential-rule Datalog engine: bottom-up chase to a fixpoint, stratified `~` negation, `#count` aggregates in rule heads, `!v` existentials, and `engine.trace("holds(o12,o31,o23)")` returning a full derivation tree (rule, bindings, subtraces) that maps back to GraphObjects and user rule names. That is the one thing no other in-process candidate has: a built-in "why does X hold?". It is also a different machine from clingo (deterministic chase, no grounding or search), built for data sizes clingo's grounder would choke on. Its language is almost exactly the ASP subset `clingoReasoner.lp` already restricts itself to, so the rule base ports nearly line for line. Install: `python3.14 -m pip install nemo-python==0.10.1` on all three platforms; cp314 wheels exist for macOS 10.12+ x86_64 and 11.0+ arm64, manylinux_2_17 x86_64/aarch64 and win_amd64 (https://pypi.org/pypi/nemo-python/json), no sdist (building needs nightly Rust). Pin the version: the bindings are self-described "experimental", releases "unstable". License MIT OR Apache-2.0: no flag. Engine class: ~450 lines of Python plus ~300 lines of `.rls`, 3-6 days to pass ReasonerSpec, mostly spent on Nemo's strict typing (`42 != "42"`), the no-tuples rule and one stratification policy decision (below).

**2. SWI-Prolog via janus-swi** (https://pypi.org/pypi/janus-swi/json, BSD-2; SWI-Prolog BSD-2; s(CASP) pack Apache-2.0). The genuinely different paradigm the design doc gestures at: goal-directed, tabled Prolog with well-founded negation. `:- table` computes the same fixpoint the ASP rule base does, but the engine can also answer a single question top-down without a full run, incremental tabling re-evaluates only invalidated tables after an edit, non-stratified user rules give "undefined" answers instead of zero or several answer sets, and Prolog is a native query language most users already know; the existing `ans(X) :- holds(T,F,X), name(T,"has"), name(F,"fred").` test query is valid Prolog as-is. Justifications come from a ~60-line meta-interpreter over the completed tables (recommended) rather than from s(CASP), which is a different evaluator with no counting and would be seconds, not milliseconds. The cost is distribution: two installs, and no bundling path. Try first: Windows: install SWI-Prolog 64-bit (https://www.swi-prolog.org/download/stable), then `py -3.14 -m pip install janus-swi` (cp314 wheel; needs `swipl` on PATH or in the registry at import). macOS: `brew install swi-prolog` (arm64 bottles; x86_64 may build from source), then `python3.14 -m pip install janus-swi` (sdist; compiles against `swipl --dump-runtime-variables`, needs Xcode CLT); the official .app installer instead needs PATH and DYLD_LIBRARY_PATH set per the janus README (https://github.com/SWI-Prolog/packages-swipy). Linux: `sudo add-apt-repository ppa:swi-prolog/stable && sudo apt install swi-prolog` (or conda-forge), then `pip install janus-swi` (sdist, needs gcc). SWI-Prolog >= 9.1.12 required. Engine class: ~250 lines of Prolog + 350-400 lines of Python, 3-5 days, plus 1-2 days for the justification meta-interpreter. Offer it to `.pyz`/source users only; the PyInstaller apps can't carry it.

**3. CLIPS via clipspy** (`pip install clipspy`, import `clips`; https://pypi.org/pypi/clipspy/json). The zero-friction third: cp314 wheels for macOS 11+ universal2, manylinux_2_28 x86_64/aarch64, musllinux and win_amd64, libclips bundled inside the wheel, no runtime, ~1-2 MB, BSD-3 bindings over CLIPS 6.4.2 (MIT-0 per the source archive's readme.txt). What a user gains is a mainstream production-system paradigm: a live, mutable Rete fact base with truth maintenance (`logical` CE withdraws conclusions when their support goes, the one real incremental story in the sweep) and CLIPS itself as a native query language. It does not add classification, proof trees or explanations. Same command on every platform: `python3.14 -m pip install clipspy==1.0.6`. Engine class: ~500-700 lines of Python + ~300 lines of `.clp`, 5-8 days, most of it proving by hand that salience strata reproduce stratified negation (CLIPS cannot check it for you). Pick this over janus if "pip install and it works in the bundled app" matters more than a new reasoning paradigm.

Runner-up to keep in mind: **Mangle via mangle-py** (Apache-2.0, 0.7 MB abi3 wheels, structured constants that make skolems and violation tuples nicer than Nemo's flattening), the lighter fallback if Nemo's instability bites, but it overlaps Nemo's paradigm entirely, its abi3 wheels were built with a pre-3.14 PyO3 and nobody has published a 3.14 test, and it exposes no traces.

## How each would plug in

Common to all three: `class XReasoner(Reasoner, engine="x")` in `src/sn/model/xReasoner.py`, rule base as package data beside `clingoReasoner.lp`, `self.facts()` rendered with a `_term()` numbering GraphObjects `o<N>` on first sight (kept in `self._objs` for the way back, as `ClingoReasoner._term` does), `_patternBody`/`_rulesProgram`/`_satisfied` transliterated, results fed to the untouched `self._finish()` so `mergeSame`/`sameClasses`/`inferredNodeFor` do what they do today. A `class TestX(ReasonerSpec, unittest.TestCase): ENGINE = XReasoner`, skipped when the engine's module can't be imported, runs the 14 conformance tests unchanged.

### Nemo

Vocabulary: `pred(a,b,c) .` one per line; GraphObject -> constant `o12`; `Sym` -> bare constant (`node`, `out`, `symmetric`) or string if not an identifier; bool -> `true`/`false`; int -> int; str and float -> `"..."` (floats as strings, as clingo does, to dodge `42 != 42.0`). `not` -> `~`, variables `?X`, `#show p/n.` -> `@output p.`. Tuples are rejected in rules (`rule.rs` `UnsupportedComplexTerm`), so `(T2,D2) != (T,D)` in `refined/3` becomes two rules, and `violation0(Code,Sev,Subject,(Args,))`/`requirement_holds(Req,(Vars,))` become flat predicates (`violation_2`, `violation_3`, ... or fixed arity with a filler; `req_<id>(?V0,...)`), reassembled into `Violation(code, sev, subject, args)` in `run()`. Values come back as `str` in angle brackets (`"<o12>"`), `int`, `float`, `bool`, or `"_:N"` for nulls; a tuple or map reaching an output predicate panics (`todo!()`), so none may.

| Hard part | Status | Concretely |
|---|---|---|
| Recursion + stratified negation | native | `isa_star`, `link_holds` through `~refined`, `holds` under supertypes, base-rule transitivity port verbatim. Caveat: Nemo checks predicate-level stratification for the whole program at `NemoEngine()` time and raises `NemoError` on a negative cycle. A user rule with a `Not` attribute test while any rule concludes attributes is such a cycle (clingo computes a stable model anyway). Policy needed: evaluate `Not` tests against an `attr_base` predicate (asserted attributes only, a small semantic change), or catch the error, drop the offending rule and report a `rule_unsupported`-style violation. |
| Counting | workaround | Aggregates only in heads, one per rule: `cnt_out(?T,?S,#count(?D)) :- card(?T,out,_,?M), ?M >= 0, holds(?T,?S,?D), individual(?S), obj(?D).` then `violation(cardinality_max, error, ?S, ?T, ?N, ?M) :- cnt_out(?T,?S,?N), card(?T,out,_,?M), ?N > ?M.` (distinct `?D` grouped by `?T,?S`: the same set semantics). Same for `_in`, `min`, `min_in` over `card_counted`. Nuisance: `<` is numeric only, so `card_merged`'s `X < N` becomes `COMPARE(STR(?x), STR(?n)) = -1`. |
| New objects + `same/2` | workaround | Nemo's `!m` nulls are opaque, unstable `_:N` and never equated with each other, and function terms are rejected, so `new(R,V,Match)` can't be written. Drop-in route: a string skolem built in the body, `?n = f"new|r12|?m|?p={?V0}"`, parsed back into `NewObject(rule, var, bindings)` in Python; `rule_new(?n)`, `fired(r12,?T,?V0,?n)`, `rule_isa(r12,?n,?C)` heads and the `~sat_n(...)` guards as `_satisfied()` builds them. `same/2` and its propagation rules stay hand-written positive rules, exactly as in the `.lp`. Termination: the base/individual guards port as is. |

Tests at risk: `test0280propertiesOfRuleObjects` and `test0950inferredObjects` (skolem encoding, same/2 merging and the `COMPARE` tie-break), `test0400violationsAndClassification` (flattened violation args), any user-rule test once the `Not`-on-attributes policy is chosen; `test0600nativeQuery` needs `language = "nemo"` queries defining `ans` plus `@output ans.`.

### SWI-Prolog / janus

Vocabulary: one Prolog clause per fact in a fresh module per run (`janus.consult('sn_run', data=text, module='sn_run')`), `:- set_prolog_flag(double_quotes, string)`, `:- dynamic`/`:- discontiguous` for the ~22 fact predicates (some absent in small models); GraphObject -> `o(12)` (keep the wrapper: violation args mix objects and counts); `Sym` -> atom; str -> string; bool -> `true`/`false`; numbers as is. After the run: `abolish_all_tables/0` and destroy the module (or keep the rule base resident and re-assert facts only; incremental tabling later). janus cannot pass compound terms to Python, so a Prolog-side `results(L)` does `findall` over the output predicates with a `to_py/2` that turns `o(N)` into `('o',N)`, `new(R,V,M)` into `('new',R,V,[Var-Value,...])` and arg tuples into lists; Python dispatches rows as `ClingoReasoner.run()` does. `consult(data=...)` prints syntax errors rather than raising, so syntax-check the generated text first (`read_term` over it) and report as violations.

| Hard part | Status | Concretely |
|---|---|---|
| Recursion + stratified negation | native | `:- table isa_star/2, isa_base/2, link_holds/3, holds/3, fired/4, rule_isa/3, rule_new/1, rule_attr/4, attr/3, same/2, refined/3, asserted_under/3, ...`; clauses transliterate (`isa_star(X,Z) :- parent(X,Y), isa_star(Y,Z).`), left recursion is fine, cyclic isa hierarchies terminate. `not p` -> `tnot(p)` for tabled goals, `\+ p` for base facts, `not_exists(attr(V,K,_))` for the non-ground user `Not` test. Prolog bodies must be ordered (binders first, negation and `\==`/arithmetic last), so `_patternBody` gains a sort step. WFS equals the stratified model on stratified programs; non-stratified user rules yield `janus.undefined`, which the engine can surface as a warning. |
| Counting | native | `aggregate_all(count, (holds(T,S,D), obj(D)), N), N > M` in the non-tabled `violation0` clauses, after the `holds` table is complete (the manual's only caveat is findall over an incomplete variant). Tabled answers are sets, so distinct `D` as `#count{D:...}`. `X < N` -> `@<`. |
| New objects + `same/2` | native | Skolems are ordinary compounds `new(o(7), "?m", ["?p"-o(12)])`; `rule_new(new(...)) :- <base-only body>, tnot(sat_n(...))`. `same/2` tabled with symmetric/transitive clauses and the four copying rules in the same SCC; the `base/1` guard bounds skolem nesting to depth 1 so tables stay finite. Only wrinkle is the results conversion layer above. |

Tests at risk: `test0260relationInheritance` and `test0245equivalenceMinusIdentity` if a `\+` runs against an incomplete table (silently incomplete answers: the port needs the tnot/not_exists discipline), `test0280`/`test0950` (compound skolems crossing to Python), `test0290noSystemNoise` (per-run module and table reset), `test0600nativeQuery` (`language = "prolog"`, strip `#show` lines).

### CLIPS / clipspy

Vocabulary: every predicate a `deftemplate` with slots (multislot `args` for variable-length violation args and bindings); facts asserted with `env.find_template(pred).assert_fact(**slots)` or one `load_facts` string; GraphObject -> Symbol `o12`; `Sym` -> Symbol; str -> CLIPS string; bool -> `TRUE`/`FALSE`; numbers native. Rules are `defrule` text passed to `env.build()`; results read with `template.facts()` and `fact['slot']` (Symbol is a `str` subclass, multifield -> tuple). Note CLIPS syntax: one CE per `not`, and variables first bound inside a `not` are local to it, so positive patterns must be emitted before negated ones.

| Hard part | Status | Concretely |
|---|---|---|
| Recursion + stratified negation | workaround | Recursion is native (agenda runs to quiescence; default fact de-duplication terminates it). Negation is operational: a `not` CE blocks an activation but a fired conclusion stays unless under `logical`. Sound port for a batch run: salience per stratum, S0 (300) everything from asserted facts only (`isa_base`, `asserted_under`, `refined`, `card_has`...), S1 (200) the positive recursive core (`isa_star`, `link_holds` with `not refined`, `holds`, fired/rule_*, `same/2`, `card_new`, `not sat_n`), S2 (100) things negating S1 (`needs_src`, `inherited`, `sub_holds`, `requirement_holds`, constraint violations), S3 (0) `inferred`, `classify`, counts, queries at -100. A stratified program's lower strata never gain facts from higher ones, so this reproduces the unique stratified model. CLIPS won't detect a wrong stratum: an error is a silently missing or extra inference. |
| Counting | workaround | No LHS aggregate. Either `(length$ (find-all-facts ((?h holds)) (and (eq ?h:t ?t) (eq ?h:s ?s) (any-factp ((?o obj)) (eq ?o:id ?h:d)))))` in a `test` CE at the last stratum, or (recommended, a few dozen lines) count the four cardinality cases in Python over the exported `holds`/`card`/`card_counted` facts after `env.run()`, since nothing downstream depends on them. |
| New objects + `same/2` | workaround | No structured terms. Register a Python callable with `env.define_function(skolem)` that interns `NewObject(rule, var, bindings)` and returns Symbol `n<K>` (or `sym-cat` a composite symbol and parse it). Finiteness as in the `.lp` (base/individual guards, `not sat_n` over S0). `same/2` closure and the four copying rules are ordinary S1 rules; `D1 != D2` -> `(test (neq ?d1 ?d2))`; canonical member `X < N` -> `(test (< (str-compare ?x ?n) 0))`. |

Tests at risk: `test0260relationInheritance` (`refined` must be complete before `link_holds` fires), `test0245`/`test0270propertiesOfTypes` (base rules through symmetric+transitive at the right stratum), `test0280propertiesOfRuleObjects` (new twins both ways, 4 answers), `test0285violationsOfProperties` (asymmetric reported once per pair; `_finish` sorts but won't hide a stratum bug), `test0400` if counts move to Python.

## Packaging notes

How clingo is handled today: `packaging/requirements.txt` is a flat list (`clingo`, `requests`, ...) with no extras mechanism (there is no `pyproject.toml` at the repo root); `makePyz.py`'s `LAUNCHER` imports `clingo` at start and exits with a pip command if it's missing; `semanticNets.spec` adds `clingoReasoner.lp` to `datas`, derives `hiddenimports` by walking every `sn/` file (so a new `sn/model/nemoReasoner.py` is picked up automatically) and appends `_cffi_backend` and `clingo._clingo` by hand; `makeUniversalWheels.py` fuses `clingo` and `cffi` for the universal2 Mac app; `modelInterface.reason/answer_query/ask_reasoner` take `engine="clingo"` as a default and `Reasoner.create` does `import_module(f"sn.model.{engine}Reasoner")`.

What "optional" should mean:

- **Dependencies**: keep `requirements.txt` for what every user needs; add one file per engine (`packaging/requirements-nemo.txt`: `nemo-python==0.10.1`; `-prolog.txt`: `janus-swi`; `-clips.txt`: `clipspy==1.0.6`), or marker lines `nemo-python==0.10.1; extra == "nemo"` if a `pyproject.toml` with `[project.optional-dependencies]` is added later, so `pip install "semanticNets[nemo]"` works. Documentation says "pip install nemo-python" while code checks `nmo_python` (the import name differs).
- **Import on demand**: `sn.model.nemoReasoner` imports `nmo_python` at module top (as `clingoReasoner.py` imports `clingo`), and `Reasoner.create()` catches `ModuleNotFoundError` for a registered-but-missing engine and raises a message naming the pip package and, for janus, the SWI-Prolog install step. The `.pyz` launcher stays as is (clingo mandatory) and only checks optional engines when the preference selects one.
- **Preference and menu**: a `"reasoner/engine": ("choices[clingo,nemo,prolog,clips]", "clingo", "...")` entry in `PREFS` (`src/sn/__init__.py`), read by `modelInterface.reason/answer_query/ask_reasoner` in place of the hard-coded default; a Reasoner menu item or the terminal's `reason --engine x`. The terminal's `ask reasoner` help should say which language the selected engine speaks (`Reasoner.language`).
- **Test harness**: `TestNemo(ReasonerSpec, unittest.TestCase)` etc., `@unittest.skipUnless(importlib.util.find_spec("nmo_python"), ...)`.
- **PyInstaller**, per engine:
  - Nemo: add `nemoReasoner.rls` to `datas`; `nmo_python` is a tiny package wrapping one extension module (`nmo_python/nmo_python.cpython-314-*.so|.pyd`), followed from `from .nmo_python import *`; add `"nmo_python.nmo_python"` to `hiddenimports` to be safe; no cffi, no data. Add `"nemo-python"` to `PACKAGES` in `makeUniversalWheels.py` (cp314 wheels exist for both `macosx_11_0_arm64` and `macosx_10_12_x86_64`; the fused binary stays inside `MIN_MACOS`). Size: +12 MB on Windows, ~+5 MB on macOS, and the Linux wheel is 53 MB (unverified whether debug info or a statically linked TLS stack; the CLI docs mention a libssl/libcrypto runtime need), so the AppImage could roughly double. Must be installed in `.venv-build` (`requirements-build.txt`) to be bundled at all.
  - CLIPS: `clipsReasoner.clp` in `datas`; the wheel is a CFFI extension plus a relocated `libclips` (`clipspy.libs`/`.dylibs` on Linux/macOS, DLL beside the module on Windows): `_cffi_backend` is already a hidden import; add a `collect_dynamic_libs("clips")` hook or `--collect-all clips` (no verified built-in hook). The macOS wheel is universal2 already, so nothing for `makeUniversalWheels.py`. +1-2 MB.
  - janus/SWI-Prolog: do not bundle. It would mean vendoring `libswipl` plus the SWI home tree (boot files, `library/*.pl`, tens of MB), `SWI_HOME_DIR` at start-up, a universal `libswipl` and `_swipl` extension for the Mac, codesigning, and GMP (LGPL)/Berkeley DB (Sleepycat) in the bundle's license picture. Ship `janusReasoner.pl` as package data in the `.pyz` only, and let `Reasoner.create(model, engine="prolog")` in the bundled app explain that this engine needs the source/`.pyz` install.
- **Licenses for the About box**: nemo-python MIT/Apache-2.0, clipspy BSD-3 + CLIPS MIT-0, janus-swi BSD-2 + SWI-Prolog BSD-2 (sCASP Apache-2.0). Nothing GPL among the recommended three; the only copyleft candidates (hermit-reasoner, IDP-Z3, Owlready2, pyDatalog) are all set aside.

## To verify before deciding

Nothing here was installed; each line is one real install away from a fact.

**Nemo (`nemo-python` 0.10.1)**
- macOS (arm64 and Intel), Windows, Linux: `python3.14 -m pip install nemo-python==0.10.1 && python3.14 -c "import nmo_python; print(nmo_python.load_string('p(1). @output p.'))"`: that the cp314 wheel is selected and imports (PyPI has no 3.14 classifier; wheels were uploaded by hand, no publishing workflow visible).

- Behaviour: that a `~attr(...)` user rule really raises `NemoError` at `NemoEngine()` (policy depends on it); that string skolems from `f"..."` round-trip as `str`; the exact stratification of `#count` rules over `card_counted`/`same`.
