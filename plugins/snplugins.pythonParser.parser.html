snplugins.pythonParser.parser module¶

Turn some Python source files – and the modules they import, as far out as asked (see readModules()) – into a Semantic Nets model (see buildModel()), built on the ontology in pythonOntology.snm (its super-model: see ONTOLOGY).

The modules analysed are parsed (with ast) only for their top-level structure:

  • Each file becomes a module, named by its file’s name (eg: reader); an __init__.py is its folder’s package instead (in Python, a package is a module: the ontology has package isa module).

  • Each folder a module is in that’s a package (one with an __init__.py, or a namespace package: see ModuleFinder) becomes a package (named by its folder’s name), whether or not its __init__.py was analysed; and so does each folder above it that’s a package. A package contains-module each of its modules, and has-subpackage each of its sub-packages.

  • A module defines (defines) its top-level classes and functions, and a code block for its if __name__ == "__main__": part, if it has one.

  • A class defines its methods (defines-method) and nested classes (defines), and inherits-from each of its bases that’s one of the analysed classes. A method is also a class-method if it’s a @classmethod, a static-method if it’s a @staticmethod, a property if it’s a @property (or its setter or deleter), an abstract-method if it’s an @abstractmethod, and an overriding-method if a class it’s derived from (one of the analysed classes: it can only tell for those) has a method of the same name: as many of those as apply. A class also depends-on-type each other analysed class that’s the type of one of its attributes (see ClassIndex.attributeTypes()).

  • A class defines (defines-attr) its variables: a class-var for each one set in its body (eg: “x = 0”, or “x:ClassVar[int] = 0”) or by a @classmethod (“cls.x = …”); an instance-var for each one declared in its body without a value (eg: “x:int”, or a dataclass’s field) or set on self in one of its methods (“self.x = …”). One its bases (those among the analysed classes) already define is left to them. A variable has its type, if it can be told (see ClassIndex.variables()), as its “attr/type” (eg: “int”, “list[Node]”), and has-type each analysed class that names (eg: Node, for “list[Node]”, “dict[str, Node]” or “Node|None”); none for a type that isn’t one of them (eg: “int”, “list”).

  • A module, class or function with a doc string has-doc a doc-string, which has it as its “text”: named by its first line (or, if that’s a field, eg: “:param x: …”, by what it’s the doc string of: eg: “go doc”).

  • A module imports each module it imports (anywhere in it): the most specific one each import names that there is (eg: for “from a.b import c”, the module a.b.c if there is one, otherwise a.b). One that isn’t analysed – further away than asked for, in the standard library or an installed package (unless asked for), compiled, built in, or not found – is an external-module (and is in its packages, if it has any).

Each module, class and function has its full dotted name as its “qualified-name” (eg: sn.model.model.Node); a module or package its file or folder as its “path”, where it’s from as its “origin” (see ORIGINS), and how many imports away from the files given it is as its “import-depth”; a class or function (or __main__ block) the lines it starts and ends on as its “line” and “end-line” (a variable the line it’s first set or declared on), and – hidden – its first line as written and a hash of its text, so that it can be found again in its file after the file’s changed (see source); a class its “bases”; and a function its “parameters” (as written).

A file that isn’t valid Python is still a module (with a note saying so), but with nothing in it.

A model made before can be brought up to date with the code, rather than made afresh, so that its views still work (see updateModel()): what’s still there keeps its node, and its id.

The model the models made build on: the types of things in Python programs (package, module, class, …).

snplugins.pythonParser.parser.ORIGINS = ('project', 'standard library', 'installed', 'built-in', 'compiled', 'not found')¶

Where a module can be from (its “origin”): the project (anything not in the standard library or an installed package: eg: the files given, and those next to them); the standard library; an installed package (site-packages); built into Python; compiled (an extension module: no Python source); or not found (eg: a package that isn’t installed).

snplugins.pythonParser.parser.SKIP_FOLDERS = {'__pycache__', 'build', 'dist', 'node_modules', 'site-packages'}¶

Folders not looked in for .py files when a folder is given (see pythonFiles()): nor are hidden ones (eg: .git, .venv).

snplugins.pythonParser.parser.SKIP_IMPORTS = {'__future__'}¶

Imports that aren’t of anything (eg: “from __future__ import annotations” turns on a feature).

snplugins.pythonParser.parser.MAX_ANALYSED = 1000¶

The most modules analysed (see readModules()): the rest are left as external modules.

snplugins.pythonParser.parser.MAIN_NAMES = {'__main__': 40, 'app': 20, 'cli': 20, 'main': 30, 'manage': 15, 'run': 15, 'start': 10}¶

Module names that suggest a program’s main module, and how strongly (see guessMain()).

snplugins.pythonParser.parser.BUILTIN_TYPES = {'bool', 'bytearray', 'bytes', 'complex', 'dict', 'float', 'frozenset', 'int', 'list', 'memoryview', 'object', 'range', 'set', 'slice', 'str', 'tuple', 'type'}¶

Python’s built-in types: a variable made by calling one of these (eg: “set()”) is of that type.

snplugins.pythonParser.parser.RECORD_BASES = {'NamedTuple', 'TypedDict'}¶

Bases of a class whose annotated class attributes are its instances’ fields (as a dataclass’s are), even with a value (a default).

The longest a doc string’s node’s name (its first line) gets: longer is cut off with an ellipsis.

snplugins.pythonParser.parser.readModules(paths, depth=0, libraries=False, progress=None)¶

Read the Python files paths, and the modules they import, as far out as depth: the files are analysed (parsed), and so are the modules they import (depth 1), the modules those import (depth 2), and so on up to depth – but only those from the project (see ORIGINS), unless libraries, and only those with Python source. The modules imported by the furthest ones analysed, and those not analysed, are there too (as external modules: see buildModel()), but not what they import.

Imports are found by ModuleFinder: first among the files given (by their dotted names: see readModule()), then next to them (see sourceRoot()), then on sys.path.

Parameters:

  • paths (list[str]) – Python files and folders (see pythonFiles()).

  • depth (int) – How many imports out from the files to analyse: 0 for just the files.

  • libraries (bool) – Whether to analyse modules in the standard library and installed packages too.

  • progress (Callable[[str], None] | None) – Told about each module as it’s analysed, if given: eg: to show progress.

Returns:

The modules: the files first (if two have the same dotted name – eg: two main.py’s in different folders – only the first is kept), and then the others, nearest first; with their imports resolved.

Return type:

list[SourceModule]

snplugins.pythonParser.parser.updateModel(model, modules)¶

Bring a model made by buildModel() (or by this) up to date with modules, in place (not saved: call its save()), so that the views of it still work: what’s still in the code keeps its node, and that node’s id (corrected: eg: its line, its doc string, a function become a method, …); what’s new gets a new node; and what’s gone from the code is removed from the model – and shows as missing in the views that showed it. (What’s matched with what: see ModelUpdate.) Anything else in the model (eg: nodes and relations of types of your own, or a note added to a class) is left as it is – except a relation to, or from, something that’s removed.

  • modules (list[SourceModule]) – The modules (see readModules()).

Returns:

What was done: what was kept, added and removed.

class snplugins.pythonParser.parser.ModelUpdate(model, reuse=False)¶

Bases: object

Makes the objects of a model of some Python code (see fillModel()): new ones – or, updating a model (reuse), those it already has, where they’re the same things.

What’s the same thing is told by a key (see node() and relate()):

  • a package or module: its dotted name (its “qualified-name”), whatever it is now (eg: an external module that’s now analysed);

  • a class, function, method or __main__ block: its qualified name (eg: “sn.model.model.Node.isa”), whatever it is now (eg: a function that’s become a class) – of several of the same name (eg: a property’s getter and setter), the first, the second, … in its file;

  • a variable: its qualified name (eg: “sn.model.model.Node.db”), whether it’s a class or an instance variable;

  • a doc string: what it’s the doc string of;

  • a relation: its type, and what it’s from and to (each by its key).

So something that’s renamed (or moved to another module or class) is taken to be gone, and something else to be new.

variables(qualified)¶
Parameters:

qualified (str) – One of the analysed classes’ qualified name.

Returns:

Its variables (not those of its bases), each once, in order: first those in its body, then those set in its methods. A variable is:

  • a class-var if it’s set in the class’s body (“x = 0”, “x:int = 0”), annotated as a ClassVar (“x:ClassVar[int]”), or set on the class in a @classmethod (“cls.x = 0”);

  • an instance-var if it’s annotated in the class’s body without a value (“x:int”) – or with one, in a dataclass, NamedTuple or TypedDict (a field’s default) – or set on self in a method (“self.x = 0”).

(Whichever is found first: eg: “x = 0” in its body and “self.x = 1” in a method is a class variable, given a new value for an instance.) Its type is its first annotation, as written (eg: “x:list[Node]”, or “self.x:Node|None = None”; ClassVar[T]’s is T’s); if it has none, what it’s first set to that tells: a new object of a class (“self.x = Node()”, or “self.x = tk.Canvas()”: a capitalized name is taken to be a class), an annotated parameter (“def __init__(self, n:Node): self.x = n”), or a value of a built-in type (see literalType()). Names like __slots__ (starting and ending with “__”) aren’t variables.
