snplugins.pythonParser.dialog module¶

pythonParser’s front end: a top-level analysis of a Python program – its packages, modules, classes, functions, methods, doc strings and imports – as a Semantic Nets model and view, opened in the editor. (The Tools menu’s “Python Parser…”: see the plugin’s register().)

It’s a dialog (see ParserDialog) listing the files to analyse – a folder stands for all the .py files in and below it – with how many levels of imports to follow from them, whether to analyse the standard library and installed packages too, and which imports to show in the view; and a “Go” button.

It makes a model of the files and the modules they import, as far out as asked (see parser), built on the ontology pythonOntology.snm (here, in the plugin’s folder), and a view of it showing the packages and modules, and the contains-module and has-subpackage relations between them – a tree, laid out left to right – and the imports asked for (see showPackages()). The rest of the model (classes, functions, …) is there to be brought into the view (eg: a module’s “expand”).

Its code can be seen from the view (see hooks): a module, class or function’s menu has “Show source” (in a window here), “Open in editor” (the “gui/editorCommand” setting’s editor) and “Reveal in Finder”; a class or function’s tooltip is its code, and a double-click opens it in the editor. It’s found in its file as it is now – after the file’s been edited – by its name (see source).

The model is named after the files’ main module – the best guess at it: see parser.guessMain() – with “_py” (eg: “XMLreader_py.snm” and “XMLreader_py.snv”), next to it (see parser.outputPaths()). (Use “save as” to keep it somewhere else.) If they’re already there, it asks whether to

  • update them (see update()): the model’s brought up to date with the code, keeping its nodes – and their ids – for what’s still there, so the views of it (the one made here, and any others) still work;

  • replace them: a new model, and view, made afresh; or

  • cancel.

snplugins.pythonParser.dialog.showPackages(view, model, showImports='given')¶

Show the model’s packages and modules, and the contains-module and has-subpackage relations between them, arranged as trees, left to right, by the tree layout (see treeLayout.TreeLayout), following “includes” (which those are kinds of), compact (subtrees tucked in beside each other); and the modules and packages in no package with nothing in them (eg: the standard library’s os and sys) each near what imports it (see treeLayout.placeNear()), or, if nothing shown does, in rows after the trees. The imports relations showImports says are shown too (their labels floating: midway): “none”, “given” (those of the files given: at import depth 0), or “all”. The tree layout is then the view’s dynamic layout (see SNGView.setDynamicLayout()): it keeps the trees arranged – eg: expanding a module opens its tree up for the classes and functions it defines.

Nothing is placed by the view (see SNGView.localLayout) as they’re shown: the tree layout places everything.

Parameters:

  • view (SNGView) – A view of model.

  • model (Model) – A model made by parser.buildModel().

  • showImports (str) – Which imports to show: “none”, “given” or “all”.

Return type:

None

snplugins.pythonParser.dialog.showNew(view, model, new, showImports='given')¶

After the model’s been updated (see update()): show, in a view of it made before, its new packages and modules, and the contains-module, has-subpackage and imports relations (as showImports says: see showPackages()) new between those it shows now – where the view’s dynamic layout (if it has one: eg: the tree layout showPackages() gave it) puts them.

Parameters:

  • view (SNGView) – A view of model.

  • model (Model) – A model made by parser.buildModel(), and updated.

  • new (list[Any]) – The objects added to it by the update (see parser.ModelUpdate.added).

  • showImports (str) – Which imports to show: “none”, “given” or “all”.

Return type:

None

snplugins.pythonParser.dialog.update(app, modelPath, viewPath, modules, options, where)¶

Bring the model modelPath – made from these files before – up to date with them (see parser.updateModel()), save it, and open its view (made afresh, if it isn’t there), showing the new packages and modules (see showNew()). Its own (and its views’) unsaved changes are offered to be saved first.

Parameters:

  • app (Application) – The editor.

  • modelPath (str) – The model’s file.

  • viewPath (str) – Its view’s file (see parser.outputPaths()).

  • modules (list[SourceModule]) – The modules (see parser.readModules()).

  • options (Options) – What to show.

  • where (dict[str, Any]) – The parent of any messages (see convert()).

Returns:

Whether it did.

Return type:

bool
