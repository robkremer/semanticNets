snplugins.XMLreader.view module¶

XMLreader’s front end: turn an XML file into a Semantic Nets model and view, and open the view in the editor. (The Tools menu’s “XML Reader…”: see the plugin’s register().)

It’s a dialog (see ReaderDialog): the XML file, and the three files made from it – for “<name>.<ext>”, by default, “<name>_<ext>.snm” (the model: see reader), “<name>_<ext>.snv” (a view of the model: its types, each with its elements round it – see showTypesExpanded()) and “<name>_<ext>_ontology.snm” (the model’s super-model: the types and definitions), in the same folder (see defaultPaths()). Any of them can be put somewhere else; and the ontology can be one that’s there already – eg: one shared by several XML files of the same kind – a file, or a URL (on the web, say). Then the model’s built on it, and what it hasn’t (eg: types for tags it hasn’t seen) is added to it – or, if it can’t be changed (eg: it’s on the web), put in the model. “Go” makes them (see convert()), asking first if the model and view are there already, and replacing them, and opens the view. (For a big file – more than MAX_SHOWN elements – the view shows just the types, to be expanded as they’re wanted: see showTypes().)

The plugin’s examples folder has some to try: books.xml (small: a namespace, nesting, comments, and elements named by their id or name), and library25.xml and library200.xml (25 and 200 made-up books: see examples/makeLibrary.py).

Created on Oct 3, 2026 (as a program of its own: a plugin since Oct 17)

Code author: Rob Kremer <robkremer@me.com>

snplugins.XMLreader.view.MAX_SHOWN = 2000¶

The most elements a view’s made showing (see convert()): a model with more shows just its types, to be expanded (see showTypes()). (A view of 1000 elements takes a few seconds to make; of 10,000, minutes.)

snplugins.XMLreader.view.GAP = 40.0¶

The room separateNodes() leaves in each cell of its grid beyond the biggest node: a node it moves is at least half this from any other.

snplugins.XMLreader.view.showTypes(view, model, arrange=True)¶

Fill the view with just the model’s node types – its ontology’s (the tags’ types, their subtypes, and any added to it), and its own (eg: ones its ontology couldn’t be given: see reader.buildModel()) – arranged as a tree, by isa, growing down (see treeLayout.TreeLayout): for a model too big to show all at once (see MAX_SHOWN). Each type can be expanded to bring in its elements, as they’re wanted. (The types are still in the ontology: they’re only shown here.)

Parameters:

  • view (SNGView) – A view of model.

  • model (Model) – A model made by buildModel().

  • arrange (bool) – Whether to arrange them (as a tree): if not, they’re all in one place.

Return type:

None

snplugins.XMLreader.view.showTypesExpanded(view, model)¶

Fill the view with the model’s node types (as showTypes()) and their elements – each type expanded one level, by isa – arranged as balloons by isa (see balloonLayout.BalloonLayout): each type with its subtypes and elements round it. For a model small enough to show all at once (see MAX_SHOWN): the types organize it, and its elements can be expanded to bring in how they nest and refer to one another.

Nothing is placed meanwhile (see showTypesAndExpand()).

Parameters:

  • view (SNGView) – A view of model.

  • model (Model) – A model made by buildModel().

Return type:

None

snplugins.XMLreader.view.showTypesAndExpand(view, model)¶

Fill the view with the model’s elements and their relations, without their types (for arrange() to arrange, as they nest: eg: for the User Guide’s pictures of the hubs layout):

  1. show the model’s types – its ontology’s nodes that are directly a kind of node: one for each tag (see buildModel()) – and expand each by expandLevels() levels (as the expand menu’s “expand all, n levels”), which brings in their individuals;

  2. erase the types (and so the isa links to them): each individual has its type’s look (see reader.TypeLooks), which shows which it is. (They’re erased as a category, so expanding won’t bring them back.)

  3. expand what’s left by 2 levels, for anything not in yet.

Nothing is placed (see SNGView.localLayout) meanwhile – nor the relations’ labels, as each new one is put between its ends once the editor’s idle (see vrelations.VRelation): what’s there then isn’t where it ends up, and placing thousands of things in a crowded view takes a long time.

Parameters:

  • view (SNGView) – A view of model.

  • model (Model) – A model made by buildModel().

Return type:

None

snplugins.XMLreader.view.relationTable(model)¶
Parameters:

model (Model) – A model made by buildModel().

Returns:

The relation table (see relationTable.RelationTable) that makes trees of how its elements nest: a row for each of the general relation types, which stands for its kinds – HAS_PART (has-<tag> and has-<holder>) and PART_OF shape the trees, each element its children’s parent (the source end of xml-has-part, the destination of xml-part-of); REFERS_TO (the references) pulls what they relate together – and one for any other relation type that none of them stands for (eg: in an ontology made before there were these), shaping the trees.

Return type:

RelationTable

snplugins.XMLreader.view.arrange(view)¶

Arrange the view’s elements as balloons, as they nest (see balloonLayout.BalloonLayout, by relationTable()): each element with its children round it, and so on out to the leaves – all at once, as one undoable command. (Not the animation layout, which was used before: it took a long time to settle with a big file, and could leave nodes on top of others.)

Parameters:

view (SNGView) – A view of a model made by buildModel(), filled by showTypesAndExpand().

Return type:

None

snplugins.XMLreader.view.separateNodes(view, gap=40.0)¶

Move each node that’s on another to the nearest free cell of a grid that nothing’s on (see freeCells()): the others stay where they are. It’s quick even with thousands. (arrange() leaves nothing on anything else, as a rule: this is in case.)

Parameters:

  • view (SNGView) – A view.

  • gap (float) – The room in each cell beyond the biggest node: a node moved is at least half of it from any other.

Returns:

How many were moved.

Return type:

int

snplugins.XMLreader.view.freeCells(boxes, gap=40.0)¶

Where to move each box that’s on another (see separateNodes()): the boxes, in order, each stay where they are if they’re on none of those staying; the rest go in the middle of the cell, of a grid of cells as big as the biggest box with gap to spare, that nothing staying or moved is on, whose middle is nearest theirs. Each box is only compared with those near it (see layout._BoxIndex).

Parameters:

  • boxes (Sequence[Sequence[float]]) – [x1, y1, x2, y2].

  • gap (float) – The room in each cell beyond the biggest box.

Returns:

The new top left of each box that’s moved, by its index in boxes.

Return type:

dict[int, tuple[int, int]]
