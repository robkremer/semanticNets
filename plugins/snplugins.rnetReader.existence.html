snplugins.rnetReader.existence module¶

The existential status of a KNet net’s nodes: Gaines’s five senses in which what a node stands for exists (section 3.5) –

  • conceptual: it’s a node of the net (each is);

  • logical: it’s consistent (it has no inconsistent link: see the kernel’s inconsistent);

  • categorical: it’s specified to be essentially a top node (a maximally generic entity);

  • singular: it’s specified to be essentially a bottom node (a single entity);

  • situated: it’s a bottom node within a universe of discourse – here, the net’s: nothing in the net but what’s equivalent to it includes it.

Whether a node is essentially top or bottom isn’t something the net’s links say: Gaines has it specified, by “extra-logical or metalogical constraints”. Here it’s the node’s EXISTENCE attribute (see specify()), and where the net’s links disagree with it – something includes an essentially bottom node, or an essentially top one includes something – the report says so.

snplugins.rnetReader.existence.EXISTENCE = 'existence'¶

A node’s attribute specifying what it essentially is: TOP or BOTTOM (see specify()).

snplugins.rnetReader.existence.TOP = 'top'¶

The values of EXISTENCE: essentially a top node (categorical existence), or a bottom one (singular existence).

snplugins.rnetReader.existence.BOTTOM = 'bottom'¶

The values of EXISTENCE: essentially a top node (categorical existence), or a bottom one (singular existence).

snplugins.rnetReader.existence.SENSES = ('conceptual', 'logical', 'categorical', 'singular', 'situated')¶

Gaines’s senses of existence, in his order.

node: Node¶
consistent: bool¶

Whether it has no inconsistent link (logical existence).

above: list[str]¶

The nodes it includes (in the net, and not equivalent to it), by name: none, it’s a top node of the net.

below: list[str]¶

The nodes that include it (likewise): none, it’s a bottom node of the net (situated existence).
